RECOVERY
Use --status after interruption/failure; it performs reads only, no signal,
patch, resume, or evidence writes. Do not repeat --apply.
--continue is an explicit recovery command: it NEVER repeats a signal or an
uncertain patch. After a recorded signal it resumes drain observation; after a
recorded patch it only accepts an already-observed exact target configuration
and verifies runtime. A recorded patch whose target is not visible stops for
review; there is no automatic retry or rollback.
Do not run --continue blindly; review --status and failure output first.

--rollback is an explicit guarded LOWERING change, not automatic. It uses the
same stop-claiming/drain/compare-and-swap process to restore the exact original
environment. It requires a healthy readable app and unchanged expected target
configuration. It cannot force-recover a crashed/unready app and must not be
substituted with an unconditional kubectl rollout undo.

The tool directory and state must remain root-owned, non-group/world-writable.
Never chmod0777 to download them. ORIGINAL/PLAN/PATCH.private.json may contain
pre-existing environment values and must NOT be downloaded or pasted.
Only the printed safe report and RESULT-*.json are intended for sharing.
