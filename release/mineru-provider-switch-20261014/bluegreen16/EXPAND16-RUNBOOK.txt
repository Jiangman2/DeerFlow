MinerU dedicated pool: six to sixteen serialized parse slots
Revision: 20261016-r1

This is an actual production capacity change, NOT another read-only review.
Run the packaged single Python file on datax-01 only, as root, with --expand.
Do not run it on datax-02/03. Python 3.7+ is supported.

APPROVED SCOPE
Only spec.replicas of six existing dedicated Worker Deployments may change:
  deer-flow-mineru-dedicated-r1-w-ecs-0011: 1 -> 3
  deer-flow-mineru-dedicated-r1-w-ecs-0012: 1 -> 3
  deer-flow-mineru-dedicated-r1-w-ecs-0013: 1 -> 3
  deer-flow-mineru-dedicated-r1-w-ecs-0014: 1 -> 3
  deer-flow-mineru-dedicated-r1-w-ecs-0015: 1 -> 2
  deer-flow-mineru-dedicated-r1-w-ecs-0016: 1 -> 2
Each Worker remains a serialized native parser (one local parse slot).
This is NOT a guarantee of 16 concurrently executing provider jobs and is NOT
approval for 32/64 slots. Local parsers and provider calls share these slots.

The existing dispatcher process, its in-memory waiting queue and busy set,
original six Worker processes, all Pod templates, images, Secrets, Services,
old zero-replica pool, WeKnora, Gateway, Frontend and Nginx are not changed.
Queue emptiness is not required. Do not restart the dispatcher or change its
MINERU_DISPATCH_MIN_BACKENDS=6: this is a readiness floor, not a capacity cap.
The exact candidate dispatcher discovers the additional Worker IPs dynamically.

datax-02/03 runtime reports were supplied directly by the operator and are
recorded with their paths and hashes, not falsely described as remotely re-read.
Prior frozen preparation/stage/switch/retirement helper files and private
snapshots must remain on datax-01. No earlier artifact or receipt is overwritten.
Keep the original tools and /var/lib evidence until release acceptance completes.

EXECUTION AND CHECKS

to install a checksum-verified private copy under a new /var/lib tool directory.
Never chmod 777 any tool or evidence. Directories must be 0700, files 0600.
The tool creates /var/lib/mineru-expand16-20261016-r1 once and refuses reuse.

Before and during the change it checks the old pool remains at zero with no
nonhistorical owned Pods, original process identities, route/Secret/policy
baselines, node leases and fresh CPU/memory/ephemeral-storage/disk headroom.
Each of six patches is server-dry-run first, then one live compare-and-swap
request testing UID, resourceVersion and the entire prior Deployment spec.
Only replicas can change. Admission changes to other spec fields are rejected.
Each step waits for readiness and exact headless endpoints, then probes the
added Workers and unchanged dispatcher before moving to the next node.
Final checks require 16 live/discovered Workers, all exact source/config/CA
checks and unchanged public routing. Read-only health probes submit no documents.
Waits are bounded; progress and retained evidence are printed. Do not interrupt
merely because a node is still starting Pods. No fixed completion time is promised.

Run the printed --status command using the same installed script, and send its
safe output plus the final receipt fields. --status reads only, does not exec in
Pods, resume the operation or import images. Preserve all private snapshots.
Partial expansion is retained for an explicit reconciliation plan. Restoring
the old route requires a separately reviewed old-pool restoration first.
