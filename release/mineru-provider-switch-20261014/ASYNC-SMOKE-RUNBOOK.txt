MinerU dedicated FC-02 asynchronous smoke probe, r1, 2026-10-14

THIS IS NOT A PURELY READ-ONLY PROVIDER TEST
It submits at most ONE new task to the operator-confirmed dedicated endpoint.
The input is a generated two-page scanned PDF with no business/user data. The
provider may retain the synthetic task and consume a small amount of quota.
No existing knowledge-base documents, user uploads or production settings change.

BOUNDARIES
Run on datax-01 as root after archive checksum verification in a new root-private
/run control directory. The host controller supports Python 3.7+. It rechecks the
four audited Deployment fingerprints, an owned ready idle-at-sample Worker and
its image/source hash. It starts one temporary Python exec process in that Pod.
The reviewed candidate module is compiled in that process's memory only. The
installed Adapter source and running HTTP service are not replaced or restarted.
No new image, dependency install, scale change, Secret read/write or database write.

The new Key is requested with terminal echo disabled. It is not included in files,
environment variables or process arguments; it crosses the authenticated kubectl
exec stdin transport and is used only as Bearer authentication to the approved
HTTPS origin. A configured enterprise CA with the previously audited hash is
required. Hostname/certificate verification remains enabled, trust_env=false,
redirects are forbidden. No verify=false or TLS weakening fallback.

APPROVED ROUTES
Submit: https://aiapi.cnooc.com.cn/MinerU2.5-2605-1.2B/FC-02/tasks
Query collection: https://aiapi.cnooc.com.cn/MinerU2.5-2605-1.2B/FC-02/dynamic/member1/mineru-for-zy-agent/tasks
Status/result URLs are built locally from one validated task ID; URLs from
provider JSON never select a destination. No FC-01 sync call or sync fallback.

LIMITS
One two-page PDF <=2 MiB, one POST, <=100 status GETs, <=10 result GETs.
Candidate task deadline 240 seconds; remote hard alarm 340 seconds including
preflight/conversion, controller transport limit about 390 seconds. Temporary
exec process memory address space <=768 MiB, CPU time <=60 seconds, core dumps
disabled. Response size <=64 KiB for submit/status and <=16 MiB for result.
Retry transient status/result failures at most twice consecutively against the
same task; never retry an uncertain POST. Existing production parse traffic is
not paused, so the idle observation is only a sample, not an exclusive reservation.

RUN
bash ./run-datax01-async-smoke.sh
Enter the NEW dedicated MinerU Key when prompted; do not paste it into commands
or send it in chat/logs. Expect progress every 15 seconds while the exec runs.
The script prints download_directory=/home/cnooc/mineru-async-smoke-download-...
with cnooc-owned async-smoke.log and RESULT.json. Return both files.

UNCERTAIN / INTERRUPTED
A root-private atomic PROBE-STARTED.json under
/var/lib/mineru-async-smoke-20261014-r1 prevents automatically launching a second
task with this package, even if the first exec connection fails. Do not delete
the marker, rerun another revision or manually repost the file. Read status:
python3 -B /the/printed/control/path/probe_async.py --status
The validated synthetic task ID, if received, is retained in the safe report for
diagnosis. A remote job may outlive a client timeout; no unreviewed cancel API is
called. A pre-submit baseline/CA failure is not evidence that credentials failed.

PASS MEANING
Async submit/query/result and candidate conversion of both page markers passed.
visual_return=NOT_CONFIRMED means image-return acceptance remains open, even if
the OCR/API smoke succeeded. No original text/image contents or raw provider
error messages are exported; only status codes/classes/counts and synthetic ID.
This does not prove business-document quality, 64 concurrency, knowledge indexing,
chat upload end-to-end latency or release readiness. ready_for_rollout stays false.
