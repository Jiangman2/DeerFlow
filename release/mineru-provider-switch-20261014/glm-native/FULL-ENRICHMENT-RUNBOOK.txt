REQUESTS AND ACCEPTANCE
- Exactly one upload and at most one vector-only search. Exclusive markers precede each operation;
  uncertainty NEVER causes the tool to submit again.
- Normal expected work: two GLM calls (OCR and caption), approximately three Embedding batches.
  These are expectations, NOT hard network-call caps. The unchanged native image task allows
  MaxRetry(3), the Embedding transport retries up to three times, and Gateway busy retries must be
  between zero and three. The test is bounded by App deadlines and Pod activeDeadlineSeconds=1200.
- Actual schema version 90 / dirty=false / required extensions must be verified in the EMPTY test DB.
  Health 200 alone does not prove successful migrations.
- After bootstrap, a separate non-superuser fixture_app role performs the real application work,
  with connection limit 24; server max_connections=40. No production DB tuning is performed.
- The real API creates models/KB and ingests the synthetic PNG. Actual Asynq processing must create
  OCR and caption child chunks. Both must have real 1024-dimensional index rows linked to this KB.
- A real query embedding must retrieve those child chunks via vector-only search. The boolean
  indexed flag and disabled-indexing paths cannot satisfy acceptance.
- Only safe counts, IDs, dimensions, error classes and content-marker booleans are exported.
  Raw document/model/DB logs and vectors are not exported.
- NetworkPolicy narrows egress, but CNI enforcement is NOT independently proven. Isolation also
  relies on clean child-process environments, loopback stores, no production store addresses/keys,
  no service token or host storage mounts, and no publicly published test API.
