  This step privately transfers both to datax-01, verifies them completely, then
  imports/unpacks/pins those two references in containerd k8s.io on that node.
  It does NOT start a database, Redis, App or Pod; connect to production stores;
  copy a runtime volume; change a Deployment, Service, model, queue or worker
  setting; submit a provider request; or rebuild any image. Native GLM client
  acceptance is PASS but real enrichment acceptance remains NOT_TESTED.

Execution
  Deliver weknora-enrichment-preload-images-20261017-r1.py to /home/cnooc on
  datax-01. Copy it to a fresh root-owned 0700 /var/lib tool directory with
  install -o root -g root -m 0600, compare the published single-file SHA256,
  then run python3 -I -B -u <private-tool>/preload.py --prepare-once.
  Keep pipefail and both Python/tee exit codes. No executable file mode needed.
  The single-file delivery freezes all imports; it loads no helper from cwd.
  Each node may ask for its cnooc sudo password and SSH login password separately.
  Both are hidden; the tool writes neither to disk or argv. It needs no GLM key.
  Keep the terminal open; do not Ctrl+C because a silent hash check looks slow.
  The source streams are paced at 16 MiB/s; OCI reads are paced separately.
  Nice/ionice bound client priority, NOT the whole containerd daemon's resources.

Checks
  Before prompting: root/datax-01/ARM64, >=4 GiB available host memory,
  private output ancestors, inode/read-only checks, required local CLI flags,
  no competing buildctl/nerdctl/ctr image import/export, exact existing reference
  identity if present. No other process is stopped, no cache/image is deleted.
  Imagefs conservative cold-import budget = reserve (max 20 GiB or 20%) plus
  2x full compressed layers + 2x full expanded layers +2 GiB headroom, for both
  absent images. /opt separately retains reserve plus remaining archive bytes.
  No presumption that shared base blobs are cached; free space rechecked live.
  Both pinned report hashes, archive bytes/hashes, OCI roots, ARM64 manifests,
  configs, every layer and DiffID, and exact import-reference annotation are
  verified BEFORE either import. Redis's multiarch index is not confused with
  its ARM64 manifest or CRI config ID. Unrelated archive references are rejected.
  Imports are sequential, --local --platform linux/arm64 --snapshotter overlayfs,
  without --digests, --index-name, --all-platforms or starting a container.
  Complete existing matching images are reused; conflicts/incomplete images stop.
  Existing target labels are merged only for the pin; no removal/unpin occurs.
