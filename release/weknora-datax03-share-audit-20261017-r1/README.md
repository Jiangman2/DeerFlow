# 保留 datax-03 数据盘：共享存储可行性只读检查

目标是让知识库文件继续位于 datax-03 的 3 TB 数据盘，不把约 250 GiB
文件迁到 ecs-zdz-pro-0000。本阶段只收集数据，尚不启用 NFS 或切换卷。

上传交付脚本到 **datax-03** 的 `/home/cnooc/`，执行 RUN-datax03.txt。
脚本通常几十秒完成，总采集预算 100 秒，每条命令有独立超时和输出上限。
返回最后 SUMMARY JSON 或这次私有 audit.log 即可，不需要业务文件。

读取内容：

- 固定目录的元数据、文件系统/磁盘余量；不遍历约 250 GiB 文件树。
- NFS/rpcbind/firewalld 服务状态、所需工具是否存在、NFS 内核状态。
- 现有活动导出与持久配置的计数、与两个知识库目录的重叠关系。
  非目标导出路径只输出散列，不输出客户端名单或原配置内容。
- TCP/UDP 2049/111 监听情况；不连接端口、不挂载、不发送 NFS 请求。
- firewalld 活动 zone 的 nfs/2049 查询；这不代表其他防火墙/ACL 放行。
- datax-03 的地址及到已核实 datax-01 地址的本地路由决策（不发网络包）。
- 间隔 5 秒的 CPU、内存、磁盘和网卡计数器。资源快照不等于持续负载余量。

不安装软件，不启动/重启服务，不改导出/防火墙/PV/PVC，不复制文件，不读
文档内容、Secret 或业务日志，不查数据库，不调用模型。脚本本身不写文件；
启动器仅新建 root 私有目录保存脚本和脱敏日志。

不存在的可选工具明确记录 NOT_INSTALLED；无法读取/解析/超时明确记录
UNAVAILABLE，不能当成“没有服务/规则”。采集不完整返回 2；主机/权限不符
返回 1；正常采集返回 0。不要因此重试任何以前的构建或变更工具。

## 后续门槛

这不是修改授权，也不自动选择 NFS 部署方式。审核结果后再准备仅测试目录的
小文件跨节点验证，确认 UID 1000 权限、实际 NFSv4.1 网络路径、原子改名与
读回一致性。生产目录导出、启动入口递归 chown、DocReader 共享路径、工作池
总槽位、DB/Redis 连接和跨实例后台任务仍需单独审核。

数据继续留在 datax-03 不等于存储高可用；该节点/磁盘故障仍影响所有副本。
保留原本地卷和原文件，不能先把新空卷挂到生产路径。

## 本地测试

package.py 在 `--network none` Linux 容器中运行合成测试、Python 3.7
语法检查及 bash -n，再生成新目录交付；不会访问任何生产主机。
