# 执行与触发规则

## 企业部署场景：定时已开启

本包按用户要求写成**定时已开启的企业运行配置**，schedule.json的enabled=true。接收方部署时注册并开启企业调度任务，按以下规则执行。文件包不是常驻调度器，单独修改JSON不会产生定时触发。本次只更新迁移交付文件，原电脑Codex任务仍保持暂停；不创建邮件/微信/企业群发送任务。

## 手动执行

用户给定D/T → 获取三个月API快照 → agent搜索并固化金融与新闻 → validate_inputs → generate_report --png → 视觉检查 → complete → 交付HTML和PNG。失败不标完成。手动历史样例可离线运行，无需定时开启。

## 定时配置及触发

企业管理员保留enabled=true，并在企业调度器配置北京时间星期二至星期六，每天06:00、06:05、…、23:55触发。采用当地墙钟时间；不要用主机默认日期代替北京时间。每轮只检查一次目标日接口，成功判定是业务成功+14项完整+日期等于T+单位/数值通过，不仅是HTTP 200。

注册参数：时区Asia/Shanghai；周二、周三、周四、周五、周六；开始06:00，结束23:55，间隔5分钟；最大并发1；不补跑停机期间积压触发。调度目标是执行 `agent/AGENT_PROMPT.md` 的完整企业agent任务，工作目录为迁移包根目录，**不是只执行probe命令**。probe返回READY或HISTORY_REQUIRED后，必须继续历史取数、金融与新闻检索、校验、出图和complete。若企业平台只有命令调度，需要其命令入口调用企业agent任务API；该调用格式由企业平台提供，不能以本包不存在的适配器冒充已接通。

示例：周二06:00请求周一报价，未齐则06:05再请求；06:10齐备则开始生成周二日报。假设06:18完成，06:20及以后触发返回COMPLETE，不再调用API。若06:15触发时尚在生成，则返回IN_PROGRESS。星期日、星期一无触发，下一周二按新的D/T执行。

`workflow_gate.py probe`实现暂停/时间窗口/当天已完成/执行锁检查，以及一次目标日请求。返回JSON含status；退出码为0仅说明检查正常，企业agent必须读取status决定下一步。目标日仅请求一次，不在该步骤自动重试。历史补采步骤可各日期最多两次，已归档的有效历史响应复用。

| 状态 | 动作 |
| --- | --- |
| PAUSED / OUTSIDE_WINDOW | 不调用API，不生成 |
| COMPLETE | 本期HTML/PNG/JSON及完成标记匹配，停止当天重复取数/交付 |
| IN_PROGRESS | 另一执行已持锁，不并发生成 |
| WAIT_DATA | 目标日未就绪、API失败或缺值，下一触发再取；不缓存为成功 |
| HISTORY_REQUIRED | 目标日已验证，补历史并继续agent检索 |
| READY | 已有有效整期API快照，继续金融/新闻/渲染 |
| NEEDS_REVIEW | 输出或状态异常，先排查，不能假定完成 |

同一期采用企业平台单实例或本包claim/release锁。锁包含日期和创建信息，不设置随意过期抢占；运行异常留下锁时先确认原进程终止再release。claim、release、complete为管理操作，不会启用调度。

生成耗时可能超过5分钟，新触发发现锁后退出。数据就绪后若金融/新闻未完成，下次复用有效油气快照继续补采；不重复API、不从头搜索已核实内容。公司动态不足五条或未读原文时不出最终稿。单个网络源失败不删除有效证据。记录失败阶段；例行等待不通知，完成/重大故障/需人工处理才提示。

当日成功后哈希记录完成，下次probe跳过API。跨日只处理新D/T，不用昨天数据替代；星期日和星期一不自动出稿。目标日休市无法取得完整API数值时当天保持WAIT_DATA到23:55，不生成伪行情，保留原因待人工策略确认。不可自行改为最近交易日发布日期逻辑。

## 完成条件

输入验证通过；输出三件套齐全、日期正确；行情和涨跌口径一致；公司动态至少五条独立事项；新闻原文可追溯且不晚于截稿；320/390/430手机宽度无溢出；PNG人工/agent已查看。complete记录三件套哈希。只有完成后才交付，不通过模型口头“完成”代替文件验收。

停止/暂停优先于所有既有定时指令；用户要求暂停时先禁用企业调度并设置enabled=false，保留规则。默认只本地生成，未经另行授权不发布、不发送第三方消息。
