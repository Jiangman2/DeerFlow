2026-10-14 企业门户 / GLM：服务器诊断与验收清单 r4

r4 共享存储补测（本次优先使用）：
  sudo bash ./run-datax01-acceptance.sh --shared-only --shared-fixture \
    --shared-parent /已审计的私有共享目录
不调用 GLM，不做网站探测，只采样两个不同节点 Gateway 并核对部署前后基线。
不宣称重新审计全部 70 个副本。父目录须已存在且满足原有安全要求；不自动 chmod。
每次新建唯一模拟测试子目录，不复用或改写上次失败现场，不初始化正式热门名单。

r3 中 writer_barrier_timeout 是模拟进程互相等待目录标记的超时，不等于已经证明
写丢失。新包改用 kubectl stdin/stdout 的就绪/开始/释放消息，不靠共享标记同步。
两个 writer 都确认就绪后才下达 GO；消息绑定 nonce、动作和 writer 编号。
断线/错误消息不得触发未授权写入。远程控制进程最长 45 秒，控制器有独立期限。
真正的共享数据文件读写、文件锁、版本 CAS、失败保护断言不放宽、不刷新缓存，
也不等待“最终一致”来冒充即时通过。失败时保留每步回执、测试目录与未知状态。
需 shared_storage.result=PASS 且各阶段完整；collection=COMPLETE 不是验收通过。

本版只修正诊断，不是热更包。r2 的采集完成不能用作验收通过：
- GLM 返回 length 时明确标记输出上限中止；后续未调用的阶段标 NOT_ATTEMPTED。
  请求 max_tokens 从 128 调整为文档流式示例的 1000，不调高思考强度、不重试。
  文档说明思考长度不受此参数约束，不能仅凭 length 推断思考占满了额度。
  保留每次 120 秒、最多 4 次调用、512000 字节/4096 帧的独立硬上限。
- 相同共享卷的静态目录 subPath 可进入只读目录预检；动态 subPathExpr、
  不同 subPath、单文件、只读卷、非 RWX PVC 与不安全权限仍拒绝。
  两个节点的父目录预检都成功后才创建全新测试目录；不修改现有权限。
  报告保留选中的挂载信息，失败时不用反复猜测目录。
- HEAD 404 不等于 GET 无法打开。干净 Chromium GET 200 只验证根页，
  诊断主动拦截跨域资源，不代表已验证实际登录页面或所有资源的访问策略。

一、现在可以一次执行（不发布、不重启、不修改配置）
在 datax-01 校验并解压本包后：
  sudo bash ./run-datax01-acceptance.sh --glm --shared-fixture

执行内容：
1. 四个 Deployment 的镜像、UID、generation、spec 摘要及前后漂移检查。
2. 当前 Gateway 全部就绪副本的相关源码摘要、依赖版本；最多 4 个并行采样。
   未就绪/正在删除的副本不会被 exec；部署期副本漂移需重新核对，不能直接放行。
3. 节点 Ready/DiskPressure 等状态、Gateway 根目录和数据目录剩余空间。
   这不等同于节点 containerd imagefs 构建/预载容量验收；最终镜像大小确定后重新计算。
4. 两个不同节点 Gateway 的 open.w.cnooc.com.cn DNS、代理/CA 配置存在性、
   当前代理路径与直连 HEAD、应用 URL 策略、独立无登录 Chromium 根页访问。
   TLS 不降级。最多每个样本 2 次 HEAD + 5 次同源 Document GET；禁止子资源、
   跨域跳转与 JavaScript。不会打开现有用户浏览器或向网站发送登录凭证。
5. GLM 的真实流式文本、函数调用、函数结果继续、单张合成红色图片识别。
   仅在终端提示时输入 API Key；不可把 Key 写在命令参数、脚本或聊天里。
   最多四次请求，每次总时限 120 秒，无自动重试、无业务工具执行。
   通过 stdin 送入一次性 Python 子进程，在内存加载候选客户端；不写 Gateway 源码。
   它验证企业接口与候选客户端，不等于候选镜像、模型选择器和生产代理路由已验收。
6. 两个不同节点、同一 RWX PVC/NFS 的全新私有测试目录：真实跨节点排他锁、
   锁超时不写入、两边并发更新不丢失、陈旧版本拒绝、替换失败保留旧值。
   也验证渠道存储在权限失败时保留测试原件；绝不读取或改写真实渠道配置。
   默认选择应用 runtime_home，但必须证明其位于相同可写共享目录挂载，父目录
   安全。条件不足则 INCOMPLETE，不创建生产热门配置、不改权限、不猜测其他目录。
   若管理员已有经核实的安全共享目录，可显式增加 --shared-parent /绝对路径。
   留存一个 portal-acceptance-随机ID 目录（少量模拟数据），不自动删除证据。

可去掉 --glm 只做非模型检查；可去掉 --shared-fixture 保持无共享目录写入。
模型凭据若曾公开粘贴，应先轮换，并在隐藏提示处使用有效新凭据。
GLM 直连，忽略 HTTP_PROXY；若需要批准的 CA，需事先在该 Pod 配置
GLM_5_3_FLASH_CA_BUNDLE。本包不会为通过测试而关闭证书校验。

日志有 source_audit / network_diagnostic / shared_storage / glm 阶段提示。
GLM 最坏约 8 分钟；整个诊断可能约 10–15 分钟。不要因为暂时没文字就重复运行。
若中断或超时，结果标为不确定，不自动重试模型调用。远程子进程自带超时回收。
末尾提供 safe_result 和 safe_log，下载这两个文件回传即可；不回传生产私有备份。
collection=COMPLETE / 退出 0 仅代表采集完成；报告中 FAIL、INCOMPLETE、
baseline_unchanged=false、来源不一致仍然是未解决项。ready_for_rollout 始终 false。

二、候选镜像生成后才可做（目前不能用旧生产镜像冒充通过）
这些步骤需冻结镜像 digest、共享目录、Secret 引用、独立测试入口、两种账号。
本包不猜测这些值，也不对当前生产临时注入功能或执行数据库迁移。

A. Gateway/Frontend 候选镜像隔离启动及来源校验，镜像内跑同一后端回归和 API 权限测试；
   仅使用一次性数据库与目录。不得在生产容器执行整套 pytest 或 seed/restore。
B. 在候选测试环境显式初始化热门名单：
     python -m app.gateway.employee_directory_seed --initialize --actor RELEASE_ID
   仅当目录、目录快照和回退方案已核准后执行。不能现在照抄到生产。
C. 使用普通用户 + 管理员两个真实账号完成：
   - 初始已公开员工热门；新发布员工默认热门；未公开草稿不出现。
   - 普通用户默认热门，“展示全部”清除过滤；普通用户无法改热门（API 403）。
   - 管理员增删标签，多标签页陈旧更新 409；刷新/跨副本读取一致。
   - 同一创建者重新发布不覆盖管理员移除；档案显示可信创建者姓名。
   - 候选 Gateway 重启后名单不丢失；备份/按版本恢复在隔离目录验证。
D. 桌面 1440px、手机 390px/320px，检查原快捷按钮与“更多”图标尺寸一致，
   文档校对、智能翻译与原四个快捷按钮并列；创建按钮移除；PPT 助手位于
   PPT 生成原有四个选项之后；更多内剩余四项两列紧凑排列。
   弹框无溢出、键盘可操作；逐一打开七个批准链接及通知旁用户指南。
   内网单点登录是否成功要用实际浏览器身份验收，服务器 HEAD 无法代替。
E. 模型选择器出现 GLM，不改变默认模型；真实文本、流式、工具继续、上传图片；
   不向浏览器暴露 Key。上传图片是否经 OCR/模型视觉走对链路需看实际用量/工具记录。
F. 实际内置浏览器打开 https://open.w.cnooc.com.cn/，确认 DNS/代理/TLS 问题消除后，
   只加入审计过的精确 origin 与地址范围；验证非授权私网、metadata/loopback、
   重定向到非授权目标仍被阻断。不得配置全私网放通或 ignore_https_errors。
