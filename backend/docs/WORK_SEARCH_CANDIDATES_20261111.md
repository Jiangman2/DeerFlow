# Work 文件名近似候选

本次基于已验证的云文档分流版本 `28b6269a`，保留该版本的源码封存和本地 R14 镜像。

## 用户行为

Work 搜索接口可能已经返回目标文件，但旧版程序要求请求名称是文件标题的连续子串，导致用户少写“年”或多加一个空格时，候选被全部过滤。

修复将候选相关性与自动读取分开：

- 在 Work 已返回的结果中保留相关的近似标题，展示文件原始名称、类型和现有读取按钮；也可回复候选序号。
- 即使只有一个近似结果，也由用户选择后继续核对正文权限和读取。
- 搜索结果完整，且只有一个完全同名文件时，沿用现有自动进入正文授权或读取的流程。
- 重名、分页未完成、响应异常时，不自动选择资源。无关的正文命中不会成为文件名候选。

近似判断只用于标题相关性和排序，不修改用户名称、Work 返回的标题或资源标识，也不改变完全同名的定义。查询次数和分页上限不增加，不扫描整个云空间。若 Work 没有返回目标文件，仍需更换关键词或提供链接。

## 验证重点

使用模拟 Work 响应核对“2023年月度工作日历”的不同写法、内部空格、全半角、轻微名称差异、年份或编号冲突，以及不相关的正文命中。

服务测试需要证明：近似候选只有在本人选择后才读取；已有正文授权不会绕过选择；唯一完全同名可继续原流程；重复同名、过期、其他用户、旧卡片和重复点击仍受原有约束。

本次不新增数据库结构、模型调用、权限或配置参数。现有用户授权、消息来源、TaskRef、候选有效期和按钮回调校验继续生效。
