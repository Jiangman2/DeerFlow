## 已验证的边界

- 当前认证入口决定消息来源。网页续聊原 Work 线程、伪造来源和其他渠道不会进入个人 Work 授权。
- Work 语义规划输出既有日历/文档意图，补问发生在 OAuth 前，授权后复用原意图。
- 普通任务退出当前 Work 任务；未执行的旧授权、预览、确认和迟到结果失效，有效 grant 保留。
- 已认领写入保留结果或不确定回执，不因用户换题而抹掉真实执行记录。
- 继续使用既有 `work_integration_records` 加密 JSON；ORM、迁移链、历史源码锁与前端运行代码均未修改。

三个独立 Python 进程共享专用 PostgreSQL 的合成验证通过：同一消息只有一个接收者、同一确认只有一个认领者；
取消与确认竞争后，迟到上下文、OAuth 安装和重复确认被拒绝，已有 grant 保留。
该验证没有调用 Work，也没有模拟70个真实 Gateway Pod或证明生产容量。

另以独立测试库放入2万条未过期历史记录、100个合成主体，由3个进程各执行40轮预留与退出。

这仅是当前开发机的小规模探针。查询计划显示 pending plan 取消仍可能扫描历史记录，成本会随历史增长；
未覆盖大量过期记录积压，也不能据此推导生产70 Pod吞吐量。灰度时应观察状态表规模、事务延迟和锁等待。

## UAT 人工复测顺序

| 场景 | 预期 |
| --- | --- |
| “读取我下周的日历”“下星期我有哪些安排” | 同为日历查询；缺授权给真实链接，有授权直接查询 |
| “帮我看看最近的行程”再回复“下周” | 先补问范围，再续接原请求；不要求重发完整句子 |
| 缺新建时长，回复“半小时” | 合并标题、开始时间和新补充；先预览，再本人确认 |
| 查询后回复“把第二条改成项目会议” | 只使用本人当前未过期候选；多义时补问，不默认最近一条 |
| 待授权时改问“解释一下光合作用” | 退出旧任务并正常回答；旧授权不再续跑旧查询 |
| 待确认编辑时改问普通问题，再发送旧确认码 | 旧预览失效，无新写入；已经开始的写入仍返回真实回执 |
| 云文档卡片/纯文本链接、读后改名或追加 | 使用当前解析目标；写入仍需预览和确认 |
| 网页新会话，或网页打开原 Work 线程输入“看看行程” | 走网页原流程，不借历史 Work 身份发起 OAuth |
| 多账号与连接切换 | 不复用其他主体的 token、候选、授权链接或确认码 |
| 模型/Work服务不可用 | 给出重试或管理员处理引导，不编造“平台未接入”或执行成功 |
