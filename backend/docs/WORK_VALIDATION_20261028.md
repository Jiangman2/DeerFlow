## 本轮修复

- 共享配置明确停用 Work 后保留停用标记，旧缓存和环境引导凭证不能重新启用渠道。
- SQL 模式的渠道拥有独立协调任务；初次启动失败或数据库异常后仍有有界自动恢复尝试，
  不依赖用户打开网页。正常约 4～5 秒检查，失败时带随机抖动退避，最长间隔 60 秒。
- 启停及配置修改共用生命周期锁，先停止旧 SDK 并等待线程退出，再替换实例。
  关闭失败保留旧实例；关闭成功但 SQL 租约释放失败时等待租约到期。

本轮两项生命周期修复没有额外增加迁移或配置参数；整体 Work 集成仍包含
`0022_work_integration_state`。该迁移接在现有 0021 后，仅新增
`work_integration_records` 及两个索引，不修改既有业务表。

## 上线时仍须验收

- 生产 70 个单进程 Gateway 共用 PostgreSQL、稳定加密密钥及相同 runtime-config。
  验证实际生产 NFS 的锁和原子替换，核算全部服务的数据库连接总预算。
- 正式入口 HTTPS、精确 OAuth 回调、应用用户身份权限、固定出口白名单和真实 SDK
  收发均须通过；本机临时出口、10086 中继和测试镜像不能用于生产部署。
- Gateway 及所有启动时执行迁移的共享库消费者（含专用 PPT Runner）均需兼容 0022。
  备份并演练从实际数据库版本升级；功能关闭不阻止启动时的数据库迁移。
- 发布前停止旧接收进程，避免新旧租约协议混用。数据库恢复或接收进程退出后可能存在
  租约到期及退避等待，健康接口正常不等于机器人已恢复，不能承诺零中断。
- 两个不同的正式 Work 测试账号分别授权，验证私有文档、授权链接、token 和确认码
  均不能跨用户使用；新建和编辑仍需本人确认并回读。
- 常规回退保留数据库表、加密记录和密钥，使用兼容 0022 的回退镜像。
  不执行会删除整张 Work 状态表的 0022 downgrade，不把恢复整库当作功能回退。
