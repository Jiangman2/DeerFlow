# 本地 UAT Work 集成（2026-10-16）

> 本文保留 2026-10-16 至 10-21 的原型及本机联调历史。当前生产化实现另见
> [WORK_PRODUCTION.md](WORK_PRODUCTION.md)；生产使用共享加密 SQL 状态和迁移 0020。
> 下文“无迁移/仅内存/重启清空”只适用于当时原型或当前明确选择的 UAT 内存模式，
> 不代表生产或 UAT SQL 模式。当前日历定位无需用户提供 event_id，以后文增强说明为准。

默认关闭、只允许 UAT 应用和指定本地测试账号。没有新增数据库表或迁移；
没有改动正式服务器或正式 Work 应用。不是可直接上线的生产授权方案。

## 三层职责和代码位置

| 层 | 应用内模块 | 职责 |
| --- | --- | --- |
| 身份授权 | `app/integrations/work/auth.py` | 不可变 Principal、绑定校验、按身份隔离的内存 token 仓库、到期/撤销 |
| 能力工具 | `app/integrations/work/client.py`、`capabilities.py` | 固定 API 源、参数白名单、文档/日程工具、预览/确认/版本检查/回读 |
| 模型编排 | `app/integrations/work/agent.py`、`service.py` | 结构化单操作提议、只读总结、OAuth 流程和消息调度 |

`app/channels/feishu.py` 仅处理 IM 传输和卡片；manager 在原有身份准入之后调用集成。
`app/channels/work_documents.py` 只保留兼容导入，不再堆放业务。
`app/gateway/routers/work_documents.py` 是专用 Bearer 鉴权的薄 OAuth 中继入口。
Work 集成不放在通用 harness，也不把凭据交给 Skill/沙箱。
后续 Skill 可编排这些类型化能力，不应自己处理 OAuth 或自行拼接任意 HTTP 请求。
`app/integrations/work/scopes.py` 集中定义授权能力包与各 API/操作的权限依赖，
不得从写权限推断读取权限，也不得合并不同用户或不同 token 的 scope 来通过检查。

- 新版 docx：读取、总结、针对正文问答；新建个人空白文档、改名、末尾追加纯文字、

## 本机测试步骤

1. 启动本地 Gateway、2801 转发、模型网络桥和 10086 回调中继。
   保持 UAT 账号与本地平台已绑定；不使用正式 App ID。
2. 私聊发送 `/work 帮助`，确认回复带 `【本地 UAT】`。
3. 发送“请总结这篇文档”并附 `https://haiyoutest.w.cnooc.com.cn/docx/<id>`。
4. 首次请求在本机浏览器打开机器人给出的授权链接，核对账号后授权。
   固定回调仍为 `http://localhost:10086/auth/callback`，无须更换 ITC 登记。
5. 文档测试示例：“把这篇文档标题改成《UAT测试》”“在文档末尾追加：本条为联调测试”。
   或“新建空白文档，名称为《UAT新建测试》”。
6. 日程测试示例：“查询我明天的日程”“在我的日历中新增日程，明天上午10:00至10:30，标题为UAT测试，不邀请其他人”。
   编辑先查询，再指定返回的 event_id、完整新标题/描述与起止时间。
7. 机器人只给预览。核对全部目标、文字、时间后，单独回复 `/work 确认 <确认码>`；
   不同意则 `/work 取消 <确认码>`。确认 5 分钟有效，只能原发送者在同一绑定私聊使用。
8. `/work 撤销授权` 清除本地个人授权、上下文、未消费授权链接和待确认计划。
   Work 平台侧的授权记录需要到其应用授权管理撤销。

### 日历一次性授权（2026-10-21）

首次使用日历功能或当前 token 权限不完整时，一次请求以下两项；已有完整授权且未过期时复用，
不是每遇到一个日历关键词就重新授权。文档请求仍只申请 `docx:document`。

| 权限 | 用途 |
| --- | --- |
| `calendar:calendar:readonly` | 获取日历、日程及忙闲信息；包括主日历、参与人核对和写入后回读 |
| `calendar:calendar` | 更新日历及日程信息；本地只用于新增/编辑已确认的个人日程 |

UAT 应用 `cli_aaec76b56d38d3c7` 需具备对应的**用户身份**权限；若此前已开通，可直接测试，
缺失时再请 ITC 开通并发布。由原消息发送者通过新的机器人链接授权。
仅有 `calendar:calendar` 写权限不等于主日历读取权限，
旧 token 不会自动升级。任意一项未返回都拒绝安装新授权、拒绝访问日历，不自动降级或使用应用 token。
Work 的更新权限本身较宽，但本地类型化工具仍禁止删除、参会邀请、会议室预订和共享权限修改；
应用侧开通或用户同意该 scope 不会自动启用这些功能。写入仍需原用户单独确认。

本次两项名称依据[海能 Work 实际权限目录](https://open.w.cnooc.com.cn/document/ukTMukTMukTM/uYTM5UjL2ETO14iNxkTN/scope-list)
及其公开目录接口 `/api/tools/scope/list`。该目录没有列出先前 r4 使用的四个细粒度 scope，
尽管部分接口文档模板包含这些名称；用户随后遇到 OAuth `20043 PermissionNameErrorPleaseEdit`。
因此本地请求和 API 校验均改用上述兼容组合，不添加会议室、请假或视频会议权限。

每次 API 调用按具体 scope 校验；写操作在预览和执行前均检查主日历查询、目标操作及回读所需权限。
Work 返回 `99991679` 时只清除该用户本次失败的授权，提示重新授权；慢请求不能清除更新后的授权。
`99991672` 提示 ITC 核查应用权限，不能靠反复授权解决。完整错误描述不透传到聊天或日志。

接口依据：[海能 Work 查询主日历](https://open.w.cnooc.com.cn/document/uAjLw4CM/ukTMukTMukTM/reference/calendar-v4/calendar/primary)、
[创建日程](https://open.w.cnooc.com.cn/document/uAjLw4CM/ukTMukTMukTM/reference/calendar-v4/calendar-event/create)、
[编辑日程](https://open.w.cnooc.com.cn/document/uAjLw4CM/ukTMukTMukTM/reference/calendar-v4/calendar-event/patch)。

## Token 和写入的强制边界

- 身份维度为 **应用 ID + Work open_id + 平台 owner ID + connection ID + workspace ID + chat ID**，
  只从已验证的私聊消息派生，不能由模型/浏览器自由提交。每次读/写及返回结果前重查连接。
- OAuth state 一次性、10 分钟有效，并绑定 HttpOnly/SameSite=Lax 浏览器会话。
  code 换 token 后调用 user_info，必须与原消息发送者 open_id 完全相同。
  转发给 B 的 A 授权链接，不能因为 B 点击成功就把 B 的 token 存到 A 名下。
- 请求文档仅申请 `docx:document`，日程一次申请上表两项 scope；检查同一用户 token 实际返回的全部必需 scope，
  缺失不假定授权成功。不使用 tenant token 兜底，不从 A 的 grant 回退给 B。
- 运行时关闭功能、切换应用或轮换应用凭据后，旧服务实例不能继续复用缓存 grant，
  校验失败会清除内存授权；不会把一个应用的授权沿用到另一个应用。
- access_token 只存在本地 Gateway 进程内，不写文件/DB、不返回浏览器、
  不传模型/沙箱/Skill、不写日志；refresh_token 不保存、不自动申请 offline_access。
  过期、重启或主动清除后重新 OAuth；这与渠道绑定是两件事，不要求反复解绑重绑。
- 模型只能输出受限规划 schema；日历先输出 CalendarIntent，由服务端定位目标后生成严格 Action。
  身份/token/URL/HTTP方法/参会者和服务端执行元数据等额外字段被拒绝。
  文档正文只给只读总结模型，不用于推导写入计划，避免正文指令直接触发操作。
- 修改计划保存完整参数、目标快照与预览的 HMAC；确认时核对身份、过期、签名和最新状态。
  文档写入带 revision；日程写前回读核对，但其接口没有通用原子 CAS 保证，仍存在并发修改窗口。
- 仅明确确认命令能执行，授权本身不能写。执行过程串行且一次消费，重复确认不能重复执行。
  日程新建使用幂等键，文档块写入使用 client_token；当前新建文档接口没有对应幂等参数，绝不自动重试。
  写入后回读核对；超时/连接中断/回读不一致标记“结果不确定”，提示人工核查，不谎报失败后自动重写。
- API 固定为 `https://open.w.cnooc.com.cn`，保留 TLS 验证、禁止重定向、禁止环境代理、
  响应上限 1 MiB；绝不拿用户发来的任意网页 URL 携带 Bearer 去访问。
- 单进程最多 32 个任务、2 个并行、64 个内存授权/计划；文档正文不超过 80,000 字符。
  元数据审计只记录操作名/阶段，不记录 token、原文或聊天内容。

## 稳定性与运行限制

- 渠道删除/重配会在 SDK 所属线程取消重连/接收任务、关闭 socket 并等待线程退出，
  不再仅清除引用。重启/移除/就绪检查共享同一把渠道锁；关闭失败保留旧 worker，禁止叠加启动。
- 接收线程存活不等于 WebSocket 握手成功。可用性检查实际 `connected`；
  握手诊断只保留 HTTP/数字业务码，SDK 日志脱敏长连接 URL 中的 ticket/access_key。
  `handshake-status=514`、`handshake-msg=1000040350` 表示 Work 报应用长连接数超限，
  不应解释成用户账号过多或本地绑定码过期；需要 ITC 核实实际配额和连接占用，
  清理残留连接且停止旧接收进程的自动重连。清理后仍需以握手成功和新绑定码消费验收。
- Feishu 在任何 reaction/卡片之前做 10 分钟有界事件去重，文件批次也过滤重复 ID，
  防止“agent 已去重但先创建的 thinking 卡片无人收尾”。绑定查询失败允许重投，不放宽准入。
- SDK 卡片更新的非零业务码不再被当作更新成功；正常阶段更新同一张卡片。
- 授权等待是完成的提示卡片，不保持 thinking；处理每 15 秒给出状态，4 分钟有界超时。
  结束时等待进行中的进度发送完成，防止进度覆盖最终结果。网络失败仍可能导致卡片更新失败，不能保证 Work 永不丢消息。
- 本机模型桥改用 `read1` 及时透传 SSE，而不是等待 64 KiB 或 EOF；不修改内网模型本身。
- 同一个 UAT 应用仍有其他服务器接收消息时，消息可能分流，导致那边提示未绑定。
  本地代码不能修好另一套数据库里的绑定，更不能安全地自动停止远端服务。
  本地回复带 `【本地 UAT】`，用于区分。要稳定端到端验收，需专用测试应用或同事协调单一接收端。
- 10086 是仅监听 loopback 的开发中继，不持有 Work 用户 token；专用中继 key 仅 Gateway/中继进程知道。
  Gateway 使用已有 webhook 自鉴权边界，不扩大浏览器登录或 CSRF 豁免。
- 此通道不持久化普通 Agent run/对话正文到业务看板；token、任务、计划和上下文重启即清空。
  真实 A/B 两账号及 Work 写入端到端验收需要测试人员主动操作；自动化不发真实消息、不修改真实数据。

- 保留三层边界，不整体重构：`agent.py` 负责自然语言意图；新增 `calendar.py`
  负责候选定位、参数补全及补问；`capabilities.py` 保留受控 API、预览确认与回读。

- 支持日期范围查询、按原时间/原名称定位，标题/描述部分修改、明确起止时间调整、
  整体提前或推后、明确保持时长。只给新开始时间而未说明结束策略时补问；新建不猜默认时长。
  同一时间多条结果列出编号，请用户选择；不得默认第一条。候选过期后重新查询。
- 查询最多 31 天，最多 5 页、每页 50 条；分页不完整或匹配超过 50 条要求缩小范围，
  不把不完整结果当唯一目标。取消日程不进入候选；全天日程可读不可编辑。

  授权撤销会清除该人的候选、补问及已知日程，仍不使用共享用户 token 或 tenant token 兜底。
- 服务端生成完整 Action 并附旧事件快照和变更字段。只改标题时 PATCH 仅发送 summary，
  未修改时间和描述保持原值；预览前及确认前核对最新状态，写后核对全部预期关键字段。
