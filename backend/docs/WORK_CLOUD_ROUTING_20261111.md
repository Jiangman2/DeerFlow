# Work 云文档按名称读取的识别修复

本轮基于正式 0716 分支 `ced7db0c`，保存于独立分支 `codex/work-cloud-routing-20261111`。

原实现用少量位置词决定规划器能否看到按名称查找能力。“云盘里”能够匹配，“云空间的”和不带方位词的“云文档”会漏掉。标题补问的后续消息也会丢失前面的来源和读取意图。

修复后，可信 Work 私聊中的规划器可根据语义判断文档查找需求、来源和具体操作。名称必须有用户文本依据。已给出的名称、来源和操作在同一待补任务中保留，下一轮只补充缺项。进入其他话题或明确提出新任务时，程序切换任务版本。授权、重名选择和正文读取仍由本人绑定和资源权限校验决定。

任务事实复用现有加密 Work 状态记录，不需要数据库结构更新。正式环境继续使用现有按名称搜索和文件正文读取配置。

## 本地验证用例

| 输入顺序 | 预期结果 |
| --- | --- |
| 读取云盘里的 团队日报汇总 | 按名称搜索，缺授权时提供授权链接，重名时提供候选选择 |
| 读取云空间的团队日报汇总 | 与上条进入同一文件查找流程 |
| 读取云文档 团队日报汇总 | 使用已提供的名称查找 |
| 帮我看看云文档里的《项目周报》 | 识别读取内容需求 |
| 读取我的云空间里的文档 → 团队日报汇总 | 先补问名称，再带着原读取意图搜索 |
| 云空间里的《项目周报》 → 总结一下 | 先核对操作，再读取指定文件 |
| 帮我读取《项目周报》 → 在海能 Work 云空间里 | 来源需要核对时补问，补充来源后保留名称和读取意图 |
| 帮我读取云空间里的文档 → 换个话题，解释光合作用 | 进入普通问答，结束原待补任务 |
| 解释云文档的作用 | 普通知识问答 |
| 读取本地桌面的项目周报.pdf | 进入本地文件引导或原平台流程 |
| 读取腾讯文档里的《项目周报》 | 按明确的外部来源处理 |
| 删除云文档里的《项目周报》 | 返回当前能力范围说明 |
| 在平台新建网页对话后发“读取云空间的项目周报” | 沿用网页来源的能力与授权边界 |

自动化使用模拟模型和 Work API，核对缺项时尚未提交搜索或申请授权、名称证据、补问续接、跨账号和跨实例隔离、过期与换题后旧授权失效。实际机器人对话和真实模型识别效果需按本表另外验证。
