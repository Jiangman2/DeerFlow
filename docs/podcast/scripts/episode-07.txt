下面进入小节：2.4 两种执行入口。

DeerFlow 的运行入口不只有浏览器聊天：

浏览器 Chat：前端调用 Gateway 的 LangGraph 兼容 API。 - IM Channel：飞书、Slack、Telegram、钉钉等渠道把消息转入同一套运行生命周期。 - Scheduled Task：调度器决定何时执行，但仍然复用正常 Gateway Run 路径。 - GitHub Webhook：外部事件经过触发策略后创建 LangGraph Run。 - 内嵌 Python Client：deerflow.client 可在 Python 进程内运行 Agent。

设计重点是“多入口、同生命周期”。入口可以不同，Thread、Run、Agent、工具、状态和事件机制尽量统一。

本集小结：请记住，本章的概念最终都要回到 DeerFlow 的运行链路中，观察它们如何影响状态、工具、事件和最终输出。
