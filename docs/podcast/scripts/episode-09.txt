下面进入小节：4.2 前端提交阶段。

前端通常先处理：

输入框中的文本。 - 上传文件状态。 - /goal、/compact 等内置命令。 - 可选的输入润色或语音转写。 - 当前模型、思考模式、Agent、知识库范围等运行上下文。

确认提交后，Thread hooks 将请求交给 LangGraph SDK 客户端。前端不应自行拼接一套与后端不同的 Agent 生命周期；它负责发起 Run、消费流和展示状态。

下面进入小节：4.3 Gateway 创建 Run。

Gateway 的核心工作包括：

校验用户是否拥有 Thread。 2. 防止同一 Thread 出现冲突运行。 3. 创建 RunRecord。 4. 对运行配置做脱敏持久化。 5. 根据 assistant_id 解析 Agent 工厂。 6. 将用户输入标准化为消息或恢复命令。 7. 注入可信的用户、Thread、WeKnora 和运行上下文。 8. 规范化 stream modes、递归上限和内部调用标记。 9. 创建 asyncio 后台任务执行 run_agent。

特别要注意：传给实际执行的 config 和写进 Run 记录的 config 不是同一份。运行时可能需要 secret，但 Run 记录、API 回显和审计数据必须使用脱敏副本。
