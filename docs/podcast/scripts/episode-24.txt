下面进入小节：页面没有输出。

依次检查：

浏览器请求是否发送。 2. Nginx 是否正确改写。 3. Gateway 是否创建 RunRecord。 4. run_agent 是否启动。 5. Agent factory 是否抛出配置错误。 6. StreamBridge 是否有事件。 7. SSE consumer 是否断开。 8. 前端 grouping 是否丢弃消息。

下面进入小节：工具不在模型工具列表中。

检查：

config tool group。 - 模型是否支持 vision。 - subagent_enabled。 - Skill allowed-tools。 - non-interactive 过滤。 - MCP cache 是否刷新。 - deferred tool 是否需要提升。 - 工具名称是否重复或与对象 .name 不一致。

下面进入小节：工具执行成功但 UI 没更新。

检查：

工具是否返回了正确的 State update。 - ThreadState reducer 是否正确。 - 是否发布对应的事件。 - 前端是否订阅该 stream mode。 - TanStack Query 是否覆盖了实时状态。 - 是否发生 checkpoint/live copy 合并错误。

下面进入小节：子任务显示失败但其实成功。

检查：

是否存在 terminal ToolMessage。 - delegations 是否被旧事件覆盖。 - task_running 是累计 usage 还是增量 usage。 - Run 结束时是否缺少 terminal task message。 - 前端是否把后续 parallel task 的 processing group 误判为前一个任务失败。

下面进入小节：19.3 阻塞 IO。

Agent 执行路径大量使用 async。文件扫描、SQLite、同步 Kubernetes client 和解析器如果在事件循环中直接执行，可能造成整个 Gateway 卡顿。当前仓库有 Blockbuster 运行时门禁和 asyncio.to_thread 相关测试。新增代码应优先：

使用异步 SDK。 - 将明确的阻塞调用移到线程。 - 不在 async Middleware hook 中直接扫描大目录。 - 不用“本地文件很小”作为长期设计依据。

下面进入小节：19.4 测试分层。

表格口述：层级，测试内容；纯逻辑，reducer、路径检查、配置解析、状态合并；Harness，Agent factory、Middleware、工具和 sandbox contract；Gateway，路由、权限、上传、Run API、CSRF；Runtime，stream、cancel、resume、checkpoint、事件顺序；Frontend unit，hooks、消息分组、Artifact pairing、分页；集成/E2E，浏览器到模型/工具的完整链路；部署回归，Docker、K8s、CA、Proxy、WeKnora、MinerU。

下面进入小节：19.5 推荐的源码断点。

Gateway：请求进入、Run 创建、配置合并、内部用户注入。 - run_agent：图启动、事件循环、异常和 finally。 - Lead Agent factory：模型解析、工具解析、Middleware 列表。 - get_available_tools：工具来源和去重。 - Sandbox middleware：sandbox 初始化和上下文注入。 - Tool error middleware：工具异常如何转换。 - StreamBridge：事件入队和出队。 - 前端 Thread hook：SSE 事件如何更新本地状态。

本集小结：请记住，本章的概念最终都要回到 DeerFlow 的运行链路中，观察它们如何影响状态、工具、事件和最终输出。
