下面进入小节：为什么 NotRequired 和 reducer 很重要。

ThreadState 字段不一定一开始就存在。例如还没有使用 Sandbox 时，sandbox 可以为空；还没有生成 Artifact 时，artifacts 可能是空列表。NotRequired 表示“这个字段可以尚未写入”，而不是“这个字段永远不重要”。

下面进入小节：0.3 Python async/await：为什么 DeerFlow 不能到处写同步代码。

下面进入小节：通俗理解。

同步程序像一个人排队办事：当前事情没办完，就不做下一件事。

异步程序像一个前台调度员：把等待网络、数据库、文件或子进程的工作交出去，在等待期间处理别的请求。

下面进入小节：什么是阻塞 IO。

下面这些操作可能阻塞当前线程：

requests.get()。 - 同步数据库查询。 - 大目录扫描。 - 同步读取大文件。 - 同步 Kubernetes client。 - PDFium/DocReader 解析。 - subprocess.run() 等待长命令。

如果它们在 Gateway 的事件循环里运行，其他用户的请求也可能一起卡住。

下面进入小节：DeerFlow 中的处理方式。

优先使用异步 HTTP/数据库客户端。 - 不能异步化的同步操作用 asyncio.to_thread() 移出事件循环。 - 解析器通过协调器串行化，而不是盲目增加线程。 - Provisioner 的同步 Kubernetes API 使用同步 FastAPI handler，让框架放入 worker thread。 - Blockbuster 测试门禁会捕获业务代码中的阻塞 IO。

下面进入小节：常见误解。

async def 并不会自动让函数变快。函数内部如果直接调用阻塞库，它仍然会阻塞事件循环。await 只有在等待一个真正可让出控制权的异步操作时才有意义。

下面进入小节：状态码的系统含义。

401：没有完成认证。 - 403：已经知道是谁，但没有权限或 CSRF 不通过。 - 404：资源不存在，或为了避免信息泄露而隐藏不存在性。 - 409：状态冲突，例如同一 Thread 已经有运行中的 Run。 - 422：输入结构或字段校验失败。 - 500：服务端没有正确处理异常。

下面进入小节：0.6 ASGI、FastAPI 和依赖注入。

下面进入小节：ASGI 是什么。

WSGI 适合传统同步 Web 应用；ASGI 支持异步、长连接、SSE 和 WebSocket。Gateway 需要在一个服务中同时处理普通 JSON API、文件上传、流式运行和后台任务，因此使用 ASGI/FastAPI。

应用启动时通常需要：

加载配置。 - 初始化数据库和迁移。 - 创建 checkpointer/store。 - 创建 StreamBridge。 - 创建 RunManager。 - 初始化 MCP 工具缓存。 - 启动必要的后台服务。

应用关闭时需要：

停止接受新 Run。 - 等待或取消正在运行的任务。 - 关闭数据库连接。 - 关闭 Redis/HTTP 客户端。 - 回收 Sandbox 或释放资源。

消息可能包含：

下面进入小节：0.8 HTTP Streaming 与 SSE。

下面进入小节：为什么普通 HTTP 响应不够。

模型可能运行几十秒。如果等完整结果才返回，用户会看到长时间空白；如果每个 token 单独发一个普通响应，又不符合 HTTP 一次请求一次响应的模型。

HTTP streaming 允许服务器保持连接并持续发送数据。SSE 是其中一种约定：服务器发送带有事件格式的文本，浏览器持续接收。

SSE 只负责传输，不负责永久保存。断线后必须依靠事件日志、checkpoint 和历史 API 重建状态。
