下面进入小节：8.2 为什么顺序重要。

ThreadData 必须先于 Sandbox，Sandbox 才知道 Thread 目录。 - Uploads 必须能访问 Thread ID 和上传目录。 - 摘要应该尽早执行，避免后续 Middleware 在过长上下文上工作。 - ToolErrorHandling 要在 Clarification 前，工具异常才能变成模型可理解的 ToolMessage。 - ViewImage 要在模型调用前注入图片信息。 - Todo 要在 Clarification 前，避免计划更新被中断截断。 - Clarification 通常放在末端，负责把工具层的澄清请求转换为人机交互协议。

下面进入小节：上下文准备。

下面进入小节：执行保护。

下面进入小节：结果整理。

例如生成标题、记录 token、发布 Artifact、生成 WeKnora 引用、更新子任务账本。

下面进入小节：8.5 自定义 Middleware。

自定义 Middleware 应：

明确它修改的是消息、工具、状态还是运行上下文。 - 说明它必须位于哪个 Middleware 前后。 - 不把不可序列化的大对象写入 ThreadState。 - 异步路径避免同步阻塞 IO。 - 对工具错误和取消保持幂等。 - 添加单元测试和至少一个运行时测试。

本集小结：请记住，本章的概念最终都要回到 DeerFlow 的运行链路中，观察它们如何影响状态、工具、事件和最终输出。
