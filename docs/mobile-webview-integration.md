# 移动端 WebView 接入与生产验收

移动端形态与桌面端共用同一套前后端和同一个 HTTPS 域名。成熟 App 直接通过 Android WebView 或 iOS WKWebView 打开以下入口即可，无需部署第二套移动端服务：

```text
https://<生产域名>/workspace/chats/new
```

## App 容器要求

- 启用 JavaScript、Cookie、DOM Storage 和第一方站点存储。
- SSO 必须继续使用平台现有的同域 HttpOnly Cookie；不得把 Token 拼进 URL、注入页面 JavaScript 或存入 localStorage。
- 文件上传应接入系统文件选择器；相机和麦克风权限只在业务需要时按次申请。
- 下载应处理服务端 `Content-Disposition: attachment` 响应，并交给系统下载或 App 自有下载管理器。
- `target="_blank"` 的外部链接由 App 明确选择在系统浏览器或受控的新 WebView 中打开。
- 返回键优先执行 WebView 历史回退；没有可回退历史时再关闭 H5 子应用。
- 生产域名必须使用完整、受设备信任的 HTTPS 证书链，禁止开启忽略证书错误或混合内容兼容模式。
- WebView 应跟随系统安全更新。发布前至少使用企业实际支持的最低 Android System WebView 和最低 iOS WKWebView 各验收一次。

## 页面适配约定

- 页面声明 `viewport-fit=cover`，并处理刘海屏安全区。
- 工作区使用动态可视高度；不支持 `dvh` 的旧 WebView 自动回退到 `vh`。
- 手机端侧栏采用抽屉式导航，路由切换后自动关闭；知识库全屏嵌入页保留可见的平台导航入口。
- 设置和产物预览在手机端使用全屏表面，桌面端继续保持原有弹窗或右侧面板布局。
- 聊天头部层级高于欢迎页输入区，侧栏、Token、导出和产物按钮不会被输入区遮挡。
- 不为移动端复制业务逻辑；聊天、知识库、智能体、定时任务、文件上传与产物下载继续走原有 API 和权限边界。

## 发布前验收矩阵

每次前端发布至少完成以下检查：

1. 竖屏宽度 320、375、390、412 像素以及短横屏。
2. SSO 登录、会话过期后重新登录、退出后 Cookie 清理。
3. 新建对话、发送消息、停止任务、历史会话切换和长消息滚动。
4. 打开/关闭侧栏，并从知识库页一次点击返回侧栏。
5. 文件上传、PPT/PDF 产物预览及下载。
6. 智能体列表、新建智能体和智能体对话。
7. 定时任务列表、创建表单和底部操作区。
8. 设置页横向栏目、内容滚动、主题与语言切换。
9. 软键盘弹出/收起、刘海屏安全区、横竖屏切换。
10. 页面无横向溢出、无框架错误遮罩、无未处理 JavaScript 异常。

## 多节点 K8s 注意事项

移动端链接不引入新的本地路径或节点路径。仍通过统一 Nginx/Ingress 入口访问，上传文件、线程产物和知识库数据必须使用现有共享持久化与服务 DNS。WebView 不得访问 Pod IP、ClusterIP、节点固定端口或沙箱回环地址。

滚动更新时保持会话 Cookie 密钥、SSO 配置、上传目录和产物存储在所有副本间一致，并在正式切流前用真实 App WebView 对灰度地址完成上述矩阵。
