# 上线初测漏洞扫描与配置核查整改

范围：2026-09-23 报告的21项扫描发现、麒麟6项和Nginx9项配置差距。应用渗透问题另行跟踪。仓库修改不代表现场修复，所有项目需有资产、端口、进程/镜像和复测证据。第3.1节33/4与明细31/6矛盾，以六条明细建账，请检查单位更正。

## 已准备的仓库变更

企业 overlay 复用的 `k8s/local-pvc/nginx.conf` 增加版本隐藏、15秒keepalive、10秒请求头读取、60秒请求体读取和客户端发送空闲超时、超时连接释放，每来源256个正在处理的请求上限及429状态。256是待压测初值，须按共享出口和上级代理汇聚量调整。仅HTTP路由层计数，TLS回环不重复计数；仅信任原有本机回环恢复地址，不扩大为任意可信转发来源。

两层监听为Nginx自身错误提供无版本JSON并显式保留原状态码，上游业务JSON及原鉴权错误处理保持原协议。TLS1.2限定ECDHE+AEAD套件，保留TLS1.3，禁用会话票据。ECDHE-RSA支持RSA证书，不等同静态RSA密钥交换。原600/660秒上游任务、上传、WebSocket超时保留。下载限速、来源白名单和防盗链等待业务范围确认。

`python3 scripts/audit_security_baseline.py --asset IP-A` 只采集当前Linux主机证据；不远程连接、不读私钥/密码散列、不写配置、不重启服务。缺工具、权限不足、超时是未知，不是通过。默认SSH上下文不覆盖Match，主机nginx不代表容器nginx。

## 资产与变更前准备

确认IP-A/B/C/D与四台主机、VIP及TLS终止层映射，不能直接用企业README中三个节点替代报告四个资产。逐层记录宿主机、NodePort和Pod/sidecar的版本、模块、镜像摘要。升级一层不代表全部入口修复。

每台目标主机本地执行，替换资产标识：

```bash
umask 077
python3 scripts/audit_security_baseline.py --asset IP-A > security-IP-A.json
```

证据含内部拓扑，只在内部流转。备份有效配置、权限、包版本、镜像摘要及部署清单，不提交凭证到仓库。验证带外恢复、非root密钥登录与sudo，保持原SSH会话。

## 麒麟六项

- 密码大写、数字、特殊字符及长度四项：检查PAM实际pwquality/cracklib调用、include链和覆盖顺序。由安全负责人确认强度；可评审至少12位及ucredit=-1、dcredit=-1、ocredit=-1，不把报告minlen=6当作企业目标，不重复插入模块。验证新密码拒绝策略，已有弱密码需受控轮换，服务账号单独评审。
- root远程SSH：先验证普通运维账号密钥登录与sudo，再设置有效PermitRootLogin no，检查Match覆盖，sshd -t后reload并验证新会话；先迁移依赖root SSH的自动化任务。
- IP转发：普通非路由主机按基线关闭并持久化；Kubernetes/CNI节点确认依赖，保留必要转发并提交有隔离补偿的基线例外，不能全节点直接设ip_forward=0。参考[Kubernetes运行时准备](https://kubernetes.io/docs/setup/production-environment/container-runtimes/)。

SSH算法清单按目标版本支持能力生成，禁止未经测试统一替换。逐台实施SSH/PAM变更，保留恢复会话。无现场证据不得声明完成。

## 发布复测与回退

1. 安全保存旧ConfigMap、部署及镜像信息；审阅差异，不随整套overlay发布不相关更新。
2. 渲染企业部署，使用将发布的同一ARM64镜像与真实挂载执行nginx -t，本地文本测试不替代现场检查。
3. 仅发布审核的Nginx配置/镜像。现有subPath及启动时复制配置意味着仅更新ConfigMap不会加载新配置，需要定向滚动更新Nginx。
4. 回归双因素/SSO、聊天流、长PPT、上传大小边界、Office/PDF预览、下载、SkillHub、知识库及浏览器WebSocket。逐个入口检查。
5. 原扫描位置复测全部21项及配置项，增加非授权与监控来源对照；记录时间、资产、端口、版本、配置摘要，例外由检查单位确认。
6. 失败时恢复本次备份的配置及镜像，定向重启Nginx并验证；SSH/PAM由原会话或控制台恢复，不全节点同时变更。

状态只用已复测通过、待整改、待核实、批准例外。仓库变更当前属于待部署验证，不能标记已复测通过。
