## 下一批：持久化幂等 admission 依赖图

已阅读固定官方目标中的 store/manager 实现及 #5258、#5393、#5401 关联历史：

- `RunRow.idempotency_key` 与可空唯一索引需新增独立企业 revision（先重新确认 head/并行改动，不能覆写官方同号但不同用途的迁移）。
- Memory / SQL store 必须统一冲突语义；SQL 唯一冲突后先 rollback，再获取已存在记录，不能留下半个 interrupt 事务。
- owner/thread 必须匹配；peer 重试返回 store-only handle，不注册为本进程的活动运行，避免陈旧状态永久占住线程（#5393）。
- Gateway 复用路径不能再挂第二个 worker；必须保留企业权限、secret-redaction、员工发布/知识域准入，并检查请求语义。
- scheduler 使用同一 occurrence 的稳定 key；HTTP key、断流/取消、多次 retry 和 MCP task 投影另有依赖，不能单靠新增一个参数宣称完成。

本轮尚未添加这些字段或启用幂等 API；按上述顺序继续实现并验证，不变更生产。
