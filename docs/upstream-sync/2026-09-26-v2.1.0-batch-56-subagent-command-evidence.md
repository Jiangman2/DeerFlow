## 实现与保留边界

- Executor 仅在存在验收条件时，从真实 AI 工具调用和对应 ToolMessage
  收集 bash 证据；不从子代理自然语言总结推断执行成功。
- 独立叶模块 bash_evidence 对齐官方命令、状态及尾部输出的有界记录。
  每项命令最多500字符、输出尾部1000字符，最多20项，按调用 ID 合并。
- 每次 stream chunk 在取消检查前收集；压缩删除旧消息时保留已收集证据。
  更新/读取均复制数据并加锁；终态以后迟到结果不能改写记录。
- shell provenance 从产生证据的子状态解析（包括 Overwrite），通过 user /
  thread scoped cached lookup 获取。缺少身份、未知能力或越界客户端均为
  unknown，绝不为核验调用 acquire 或不带归属的 get。
- 零退出码不能覆盖工具已报告的 error / partial 状态；避免巨大整数解析，
  错误日志不输出凭据。AIO 普通命令能力仍为 unknown，不冒称 fresh shell。
- 证据收集与 receipts 开关独立；没有验收条件的普通任务路径不增加收集。

独立执行测试暴露了现有 Executor mock fixture 的导入顺序依赖：报告条件
规范化需要真实 sanitizer，而 fixture 已替换其父模块。通过在 fixture 内
预加载真实模块修正，不在生产代码中增加缺依赖放行。

## 验证

新增37项采集器测试和8项 Executor 组合测试。最终九模块包含采集器、
Executor、确定性验收、回执传输、委托台账、task 和 report contract：

- Windows：**582 passed, 14 skipped**，14.16s。
- Linux：**595 passed, 1 skipped**，33.54s；无网络/拉取、只读源码、非 root，
  1 CPU / 3 GiB。Windows跳过的13项权限、FIFO、符号链接检查在Linux执行。
- 两平台共同跳过项需要 LangGraph >=1.2.6 的 root-lineage 支持。
- fixture修正后的三模块独立复验142 passed / 1 skipped；Ruff检查、格式及
  scoped diff check通过。上述计数重叠，不能相加为总通过数。
