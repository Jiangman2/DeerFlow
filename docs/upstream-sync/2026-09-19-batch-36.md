# Upstream Sync Batch 36

## Scope

- Adapted upstream `3dc895df4` (opt-in model request admission).
- Included the immediate FIFO handoff correction from upstream `53dde30d4`.
- Preserved the enterprise model factory, tracing, DeepSeek/Codex/MindIE
  normalization, retry middleware, and multi-replica deployment behavior.

## Behavior

- No runtime behavior changes unless a model declares `request_admission`.
- Configured calls share a bounded, process-local FIFO and are evenly paced by
  request-per-minute budget without accumulating idle burst credit.
- Explicit groups share a limiter across model profiles; conflicting live
  policies fail construction instead of silently resetting quota state.
- Provider SDK retries are disabled only for models using admission; DeerFlow
  middleware retries remain paced and local queue failures are non-retriable.
- Immediate admission and FIFO insertion are decided under one lock, preventing
  an older blocking caller from being overtaken during queue handoff.

## Enterprise safety

- The feature is opt-in and does not alter current production configuration.
- It does not mutate databases, Kubernetes resources, WeKnora, SkillHub,
  Sandboxes, scheduled tasks, or the enterprise Gateway transport.
- The limiter is deliberately process-local. Operators must divide an external
  quota across Gateway replicas before enabling it in production.
