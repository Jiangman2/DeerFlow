# Upstream Sync Batch 19 — Serialize SQLite Scheduler Budget Claims

## Scope

- Enterprise branch start: `9c72b29b3`
- Recovery tag: `enterprise-pre-upstream-batch19-20260919`
- Official change adapted: `b0cb3a3a8`

## Behavior

- Reserve SQLite's database-wide writer before counting executing occurrences.
- Keep the count and queued-to-launching promotion in the same transaction.
- Prevent claims for distinct queued rows from concurrently exceeding
  `scheduler.max_concurrent_runs`.
- Preserve the existing PostgreSQL advisory-lock path unchanged.

## Enterprise adaptation

Production uses PostgreSQL, so this change does not alter its scheduler locking
path or require a migration. It closes the equivalent race in SQLite development,
test, and emergency validation environments. Queue admission, per-thread FIFO,
lease fencing, and enterprise run dispatch remain unchanged.
