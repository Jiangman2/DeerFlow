## Behavior

- Prefer a complete-line cut for long text so a partial source line is not
  presented as if it were complete.
- Name the exact absolute `start_line` for the next read, including when a
  ranged continuation is itself truncated.
- Handle near-budget long lines explicitly: re-read the whole line when it can
  fit alone, or direct the caller to a character-oriented bash read when no
  `read_file` call can return it whole.
- Preserve line-span and end-of-file information for bounded and open-ended
  ranges, including blank lines.
- Compare exact normalized line windows in loop detection. Sequential pages no
  longer collapse into a 200-line bucket, while repeated identical pages still
  reach the existing identical-call hard stop.

## Enterprise adaptation

The enterprise branch retains its established `start_line=0` compatibility
behavior, treating it as line 1 instead of adopting the official rejection.
It also retains the existing full-read-then-slice provider path and the larger
150,000-character budgets for installed Skill entry points and references.
This batch changes the public continuation and repetition contracts without
mixing in the separate remote-provider range-read architecture.

Long PPT/Skill workflows retain their enterprise 120/240 per-tool frequency
overrides. Exact read-window keys improve those workflows because legitimate
pagination no longer consumes the 3/5 identical-call budget.
