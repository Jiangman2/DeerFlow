## 行为与企业适配

- 同一 LangChain run ID 只持久化首个回调的 generation 集合。与已有 Token 和摘要去重保持一致，避免 append-only 消息分页重复。
- 缺失或全零 usage 暂存到下一事件/flush；相邻回调只可补 usage。已越过顺序边界的迟到 usage 只补 run 计数，不能重写旧历史或追加回答。
- 冻结摘要和嵌套 usage；不同 run ID、短/长 generation replay、关闭及失败后 flush 重试均保留官方语义。
- 保留企业 start-time caller / `lc_source` 解析，防止内部摘要丢失 tags 后被记成主 Agent 回答。重放不能改变 fallback 或 tool-call 归属。
- 企业 interrupted-artifact 校验使用深拷贝的首个 lead AIMessage，避免 provider 后续修改影响交付检查；显式宿主 `reconcile_ai_message` 仍可写入同 ID 的失败替换，迟到回调不得撤销它。
- 进度快照在 canonical response 入队后生成；失权关闭丢弃 pending response 及 caller map，不启动后续写入。PPT external usage/delivery 协议未改动。

## 验证

新增真实 AIMessage 回归先得到 **19 失败、1 通过**；观察到重复消息、可变对象影响交付快照等实际缺口。实现后 125 项关联用例通过。旧 convenience tests 按官方时序在无 usage response 的最终 flush 后断言摘要，另保留自动阈值 flush 的验证。

扩大 Windows 关联回归 **469 通过、7 跳过，19.95s**：journal、event store/API、worker 终态/取消/回退/交付、manager、PPT runner 及外部交付回执。跳过项为条件后端用例，不冒充真实生产验证。上述数字重叠，不累计。

独立 Linux 关联复验 **269 通过、无跳过，44.58s**。缓存依赖镜像 `deerflow.local/multiworker-r4-r7-compat-base:local`，非 root、无网络、只读源码及根文件系统、1 CPU/4 GiB/tmpfs；临时容器已自动移除。覆盖 journal、blocking-I/O gate、worker 取消/交付/回退/清理及 PPT runner，未使用旧镜像源码替代工作区。

Ruff/format 通过。没有安装依赖、构建候选镜像或连接生产。当前去重为进程内单个 Journal 的 callback 去重，不是跨进程全局幂等；不删除/迁移已有重复历史，也不改变已完成 run 的历史数据。整体完整回归和上线验收仍未完成。
