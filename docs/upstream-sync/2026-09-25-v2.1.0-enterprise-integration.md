## 2. 如何判定“吸收了官方更新”

每个相关提交/功能最终需要记录：官方 commit/PR、前置依赖、企业对应文件、企业差异、回归测试、配置/数据迁移、候选验证结果。

最终人工分类必须区分：

1. 原样合并，且当前实现和测试仍成立。
2. 语义等效/企业适配，明确维护的差异及对应测试。
3. 待合并，包含依赖链，不只摘最终一条修复。
4. 不适用或保留为可选后端，写明依据；“暂时困难”不能当成不适用。
5. 上线受阻，注明缺少的真实环境验证。

当前自动台账只标记 `NEEDS_REGRESSION_REVIEW` / `NEEDS_SEMANTIC_REVIEW`。历史文档中同时有已适配、延期、跳过内容，因此匹配到 SHA **永远不自动标 PASS**。关键词分类只用于分流，不能证明模块依赖完整。历史提交可能被后续覆盖；缺少同一 SHA 也可能已有企业版等效实现。

## 3. 实施顺序及保留边界

下表是尚待执行和验证的工作流，不是已完成功能列表。各流优先采用正式标签上的实现及测试，避免将长期目标缩成少量零散修补。跨流依赖仍须按代码实际关系调整。

| 顺序 | 官方能力/修复 | 企业适配与验证重点 |
| --- | --- | --- |
| 0 | 固定 2.1.0 源码、依赖及测试；建立隔离集成工作区 | 在任何合并前清点并保全共享工作区；不 reset、不把未完成数字员工代码无审查捆入发布；镜像和 ConfigMap 有效源码分别锁定 |
| 1 | 配置结构、数据库/checkpoint、认证 principal/RBAC、请求 trace、启动/取消/关闭和 readiness | 建立迁移依赖图，解决企业迁移编号冲突；保留 CNOOC SSO、管理员只读、OA/渠道身份、知识权限；旧线程和旧镜像回退不能只做空库测试 |
| 2 | Sandbox Ownership、执行租约、持久化跨 worker 取消、DB 事件/Redis bridge、多实例 scheduler | 不覆盖现有较新竞态补丁；普通 AIO 与 PPT Agent Host 保持双镜像/双容器分工；环境白名单采用保留合并，不能再次覆盖 NO_PROXY 等既有项；共享 PVC 与失权销毁必须实测 |
| 3 | 工具执行回执、子代理结果验证、acceptance criteria、扇出/并发控制、batch_task、snapshot、步骤持久化 | 父层确定性验收，不把模型成功声明当回执；跨用户/线程的产物句柄不能通用；队列租约、重试、取消、暂停/恢复和幂等性与进度 UI 一起闭环 |
| 4 | Skill 托管投影、Agent 能力目录、Projects、分支/引用会话、定时任务页面/API | 保留个人/广场员工 ID、SOUL、头像和未知配置字段；协调尚未发布的 Skill 快照/知识问答授权/版本管理；覆盖 Slash、继续、重试、分支、子任务、渠道和定时任务入口 |
| 5 | 可插拔 Memory、FTS5/BM25、事实合并/修剪、纠错与 agent 隔离 | 保留旧数据并完成显式可验证转换；不因旧 .json 配置被新版本忽略而丢失可见记忆；新外部后端只是可选，不默认发送企业数据到外部服务 |
| 6 | 树外扩展、其余 sandbox providers、MCP 与运维工具、其他前端修复 | 先稳定宿主接口和生命周期，再迁移合适的企业扩展；不能用一次大重构替代现有安全边界；可选供应商不强制新建账户/联网/增加生产服务 |
| 7 | 完整回归、离线候选构建、生产等效验证、受控上线 | 基线稳定后重新采集；隔离构建、资源限制、离线依赖闭包、精确镜像预装、备份恢复演练；用户决定上线窗口后再给生产操作指令 |

多实例“代码兼容”与“生产开关启用”分开验收。Redis Ownership 本身不能解决 Browser Live 进程内会话或企业渠道重复消费；这些未闭环时不增加 Gateway 副本/worker，也不在活动任务期间缩容。

## 4. Breaking changes 的具体处理原则

| 变化 | 必须完成的兼容工作 |
| --- | --- |
| X-Trace-Id | 校准 Nginx、Gateway、PPT Bridge、渠道/OA 调用及持久化 run；不继续信任客户端 context 中的 trace 字段；认证/错误响应也需测试 |
| /mnt/skills、HOST_BASE_DIR | 逐条迁移 Gateway、Provisioner、挂载、路径映射、个人和已发布 Skill 投影；不能把共享 Skill 仓库全部暴露给普通沙箱，也不能切断 ppt-master 的独立只读 Skill 来源 |
| 嵌套 SKILL.md 不再独立注册 | 为 vendored ppt-master、academic-research、SkillHub 安装和企业 Skill 做包边界测试；历史启用项和 Slash 入口给出明确兼容策略 |
| memory.backend_config / storage_path | 盘点用户/员工存量记忆，备份、迁移、计数/归属验证和回退；旧文件保留，不把路径变更当“自动成功” |
| checkpoint_delta.snapshot_frequency=10 | 验证旧配置读取与显式迁移；测量 PostgreSQL 存储/IO和回放行为，不能因新默认值就承诺性能改善 |
| Compose 默认 loopback | 保留生产 Kubernetes/Nginx 单入口；开发/离线验证环境需要对外访问时显式配置，不顺手扩大服务暴露面 |
| E2B 进程容量上限 | 保留为可选 Provider 的明确准入语义；企业当前 AIO/K8s 容量另行核算，不套用 E2B 行为来解释所有沙箱 |

现有企业账号、员工、线程、上传文件、知识库、Skill、记忆及已正常工作的中文 PDF/PPT/渠道功能都是保留对象。旧数据库与文件不能通过初始化或重建替代迁移。

## 5. 上线完成标准

- 目标范围内的相关功能完成语义分类，无未解释的核心行为缺口；已存在的新版补丁不被降级。
- 官方回归与企业回归均执行，区分本地单测、Linux/ARM64、真实 PostgreSQL/Redis/NFS、双用户 SSO/WeKnora、浏览器页面验收。
- 数据迁移在有存量数据的副本上验证；发布后新增/修改的数据也纳入回退兼容，而非只证明“上线前备份可恢复”。
- 新 Memory/provider/extension 及多实例开关按部署选择启用，不以全部默认开启来宣称升级成功。
- 普通对话真实命令/文件读取、PPT 独立流程、Agent Skill 和知识权限、取消/重连/owner 故障、调度重启恢复、渠道去重均有证据。
- 离线包禁止构建期临时联网补依赖；依赖增量和镜像解包峰值预估后再安排节点磁盘空间。
- 镜像之外的 ConfigMap 挂载源码、配置、共享 Skill 和数据库版本都纳入候选/回滚清单。任何旧基线漂移重新审计，不绕过门禁。
