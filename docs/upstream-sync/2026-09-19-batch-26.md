# Upstream Sync Batch 26 — Trustworthy Remote Directory Listings

## Scope

- Enterprise branch start: `a2dce65ef`
- Recovery tag: `enterprise-pre-upstream-batch26-20260919`
- Official behavior adapted from:
  - `d8ed8160c` — stop list_dir from reporting failures as empty
  - `15a9a87fb` — reject incomplete remote list_dir results

## Behavior

- A shared bounded `find` command now records `find`'s own status after the
  `head` pipeline, so a missing binary or traversal failure cannot inherit
  `head`'s successful exit status.
- Missing roots raise `FileNotFoundError`; command failures, missing status
  markers, empty SDK responses, and partial unreadable traversals raise
  `OSError` instead of being presented to the model as an empty directory.
- `find -H` follows only a symlinked starting root, preserving the intended
  remote mount behavior without recursively following arbitrary symlinks.
- A cap-induced `SIGPIPE` remains a valid bounded listing, and trailing
  whitespace in legal Linux filenames is preserved.
- The contract is applied to the remote providers present in this enterprise
  branch: AIO Sandbox, E2B, and BoxLite. LocalSandbox now also distinguishes a
  missing/non-directory root from an existing empty directory.

## Deliberately deferred

Remote glob/grep command-status and truncation propagation is a separate shared
protocol and remains for the next batch.

## Verification

- Remote-list parser, AIO, E2B, BoxLite, LocalSandbox path/mount, search-tool,

- The 9 skips are platform-conditional POSIX/symlink cases. The 5 deselections

- Targeted `ruff check`, clean-file `ruff format --check`, and
  `git diff --check` pass. The known pre-existing whole-file format drift in
  `aio_sandbox.py` and `test_aio_sandbox.py` remains intentionally untouched.
