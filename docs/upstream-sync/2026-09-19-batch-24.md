# Upstream Sync Batch 24 — AIO Shell Session Lifecycle

## Scope

- Enterprise branch start: `56a806586`
- Recovery tag: `enterprise-pre-upstream-batch24-20260919`
- Official behavior adapted from:
  - `9e0fbd60f` — isolate concurrent subagent shell sessions
  - `d8d110c63` — prevent AIO subagent session eviction

## Behavior

- Run every environment-bearing `bash.exec` command in an explicitly created
  transient session and close it after the command, including failure paths.
- Distinguish a structured `Session not found` response from a route-level 404.
  Recreate a disappeared session once without incorrectly disabling the whole
  Bash API; bound a repeated disappearance to one retry.
- When the legacy implicit Shell session emits `ErrorObservation`, retain and
  reuse the healthy replacement session for later unscoped commands instead of
  returning to the known-corrupt implicit session.
- If that retained session is evicted by the AIO runtime, recreate it once.
- Release the retained recovery session when the host-side Sandbox client is
  closed. Cleanup remains best-effort and cannot mask successful command output.

## Deliberately deferred

This batch does not claim complete concurrent-subagent isolation. The official
scope model depends on a process-local Sandbox execution-lease manager so one
subagent cannot park and close a shared client while another subagent still uses
it. That lifecycle authority is absent from the enterprise branch and overlaps
its deterministic user/thread identity, warm-pool handling, cross-process
Gateway/PPT Runner execution lease, and Provisioner behavior.

The following stay together for a later dedicated batch:

- per-subagent persistent Shell scopes;
- process-local acquire/release reference ownership;
- `MAX_SHELL_SESSIONS` sizing from the effective subagent concurrency;
- Local and Provisioner capacity inspection, propagation, and replacement.

## Verification

  session creation/closure, cleanup failure, and bounded retry.
- AIO backend, readiness, provider, Provisioner, PVC, Kubernetes config, warm
  pool, and GitHub token plumbing regressions pass on the Windows development
  host when the two pre-existing POSIX-only LocalSandbox subprocess tests are
  excluded.
- Targeted `ruff check` and `git diff --check` pass.
- `ruff format --check` still reports pre-existing whole-file formatting drift
  in `aio_sandbox.py` and `test_aio_sandbox.py`; this behavior batch deliberately
  avoids a mechanical rewrite of unrelated lines.

## Operational impact

No production workload, database, Kubernetes manifest, WeKnora, SkillHub,
Provisioner, or Sandbox image is changed. A future backend image rollout will
pick up the host-side session lifecycle behavior. Production AIO Browser and
MCP Browser remain disabled by the enterprise runtime policy.
