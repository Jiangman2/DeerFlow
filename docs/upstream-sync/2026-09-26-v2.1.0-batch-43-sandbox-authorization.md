# 批次 43：沙箱执行授权与企业复用边界

依据锁定 v2.1.0 `345f08be00c8a9495079b732a39b46aa9af1584e`
的 sandbox_authz、tools、SandboxMiddleware 与 read-before-write 最终行为。
未整文件覆盖现有租约/员工实现，未启用生产授权。

## 实现

- sandbox:execute 在同步/异步冷分配、已有 ID 复用、eager 初始化前检查。
  旧 sandbox_from_runtime 同样检查，并补齐用户/线程归属及发布 Skill 挂载验证。
- eager 拒绝不分配沙箱，普通非沙箱对话仍可继续；工具调用返回明确拒绝。
  显式 deny 不因 fail_closed=false 或 read-before-write 的检查异常放行。
- 配置读取、provider discovery 异步路径离开主循环；provider 构造及
  aauthorize 留在当前循环。尊重 existing scoped AppConfig。
- 组合文件操作共享一次实时授权判断，异步转同步工具体不重复构造
  loop-affine provider。permit 在私有 ContextVar，绑定 runtime 对象、
  thread 和 Principal 深拷贝；退出作用域失效，不能继承到下一调用或别的用户。
- 企业发布撤销、沙箱归属、只读发布挂载检查不被 permit 跳过。
  GraphBubbleUp 不转换成授权结论或普通工具失败。

## 有意的企业差异

官方 safe_app_config 将任意配置异常视为 None/关闭，本分支不采用。
只有有效 AuthorizationConfig 明确 enabled=false 才关闭检查；配置不可读、
缺失、畸形或 Mock 均拒绝且不将配置值回传给用户。
三个旧 sandbox-only 测试模块显式选择 disabled_sandbox_authorization fixture；
该 fixture 非全局 autouse，不屏蔽配置故障/授权测试。生产默认配置仍为关闭。
