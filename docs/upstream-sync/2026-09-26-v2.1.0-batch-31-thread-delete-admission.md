# v2.1.0 批次 31：删除入口接通及取消保护

继续批次 30，采用固定官方 v2.1.0 #5535（`26437b61d0b402ddaee4ef943e0fd84635d641e3`）最终入口语义；内部删除 reservation 复用批次 10–12 的已适配机制。

## 行为

- 保留现有认证、权限、必须存在且归属当前用户的检查；先授权，再取得 goal lock 和 durable `ThreadOperationKind.delete` reservation。有活动 run / 内部操作时返回 409，不能删除工作目录。
- 一次捕获 owner，传给工作目录、run 历史、事件、feedback、thread metadata。事件后端先检查 callable 签名，兼容旧单参数接口；后端抛 TypeError 不能触发无 owner 重试。
- 历史 run 删除不能删除当前 reservation；保留普通 runs 的独立用户、线程范围与企业 browser session/cookie 回收。
- 已授权的旧格式 thread ID 可清理 metadata/checkpoint，但不能构造宿主文件路径。正常 ID 的文件删除仍必须成功，否则中止后续清理，不返回虚假成功。
- 文件删除移至既有 file-I/O pool，取消请求时 drain 后再释放准入；否则后台 rmtree 可能删除新 run 刚创建的目录。这是保留企业异步取消安全的适配，不更改存量文件布局。
- 没有 RunManager 时失败关闭（503），不降级为无互斥删除。没实现 bulk cleanup 的旧 RunStore 继续兼容；可选反馈后端可缺省。

## 验证进度

新增测试先得到 15 失败、1 通过，覆盖当前入口缺失的保护。接通后校正一个合成 owner fixture，首轮关联回归 185 通过、无跳过（42.57s）。扩大后的 Windows 联合回归 **380 通过、无跳过，88.31s**，包含真实临时 PostgreSQL / SQLite / memory 的双 manager 准入竞争、HTTP checkpoint 编辑、认证、元数据隔离、事件锁、JSONL I/O、run 历史及 feedback。与前述 185 和批次 30 的结果重叠，不累计。

本机合成测试数据库验证结束后核对容器 ID/名称/本任务标签，停止并自动移除；其 tmpfs 临时数据随之释放。未删除任何企业数据或已有镜像。Scoped Ruff / format / git diff whitespace 通过。

检查所有清理阶段的 reservation 仍存在，竞争者用 reject / interrupt / rollback 均不能抢占；事务结束后新生命周期可重新准入。另覆盖未授权请求、缺少 manager、文件删除失败、每个后端失败独立处理、旧后端签名、重复取消等待文件 worker 等。未创建并行任务，未连接生产，未制作镜像。

独立 Linux HTTP 删除及批次 28 第四轮相关模块：175 通过、2 PostgreSQL 条件跳过，23.98s；这两个用例已在上述真实数据库组执行。临时测试容器均已结束，无遗留构建或数据库服务。

## 不夸大的边界与后续

- 与官方一致，各历史存储清理为 best-effort，不是跨文件系统、多个数据库、浏览器的分布式原子事务，不承诺存储故障下彻底删除。
- reservation 防护 run/checkpoint/delete 准入，不是永久墓碑；已准入 feedback 写入等其他路径须另审计。
- 仍要复核进程内 terminal cache、删除后的读取授权及跨进程旧缓存失效，不能把存储层清理等同于所有可见历史生命周期已验收。
- 无新 schema 迁移；`delete` 使用已有内部 operation_kind 列。旧镜像不了解这一 enum；有内部记录时禁止以旧镜像混跑/回退，正式发布仍需旧数据与回退演练。
- 完整 Linux 回归第四轮发现的阻塞及定向修复见批次 28；全套仍未通过。ARM64、共享存储、真实 SSO 双用户、离线候选及生产基线仍未验收。生产热更暂停不变。
