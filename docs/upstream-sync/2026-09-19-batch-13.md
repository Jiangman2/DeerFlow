# Upstream Sync Batch 13 — Cancellation-Safe Memory Shutdown

## Scope

- Enterprise branch start: `567fa4dcb`
- Recovery tag: `enterprise-pre-upstream-batch13-20260919`
- Official change adapted: `2bdae7518`

## Behavior

- Resolve shutdown-time application configuration and the configured memory
  backend off the event-loop thread.
- Treat configuration resolution, backend resolution, and the bounded
  `shutdown_flush()` call as one owned operation.
- Drain that operation through repeated Gateway lifespan cancellation, then
  propagate the first cancellation only after the worker is terminal.
- Preserve the enterprise branch's existing best-effort behavior for invalid
  shutdown configuration, disabled memory, backend errors, and flush timeout.

## Enterprise adaptation

The official branch also coordinates a newer retrieval-index warm-up task and
calls a backend `close()` hook. Those lifecycle concepts do not exist in this
enterprise baseline, so this batch intentionally does not import them. The
adaptation is isolated in `app.gateway.memory_shutdown` to keep its regression
tests independent from global FastAPI construction and production-like root
configuration.

## Operational impact

This changes only Gateway graceful-shutdown ordering. It does not mutate
production, Kubernetes resources, databases, memory files, model settings, or
live workloads. Kubernetes can still force `SIGKILL` after its configured grace
period, so the memory flush budget and surrounding shutdown work must remain
within `terminationGracePeriodSeconds`.
