## 契约

1. 开启或关闭增强日志/外部 tracing exporter，都为每轮继承或建立一个 ID。
2. 在构造 agent 前复制并覆盖保留的 `metadata.deerflow_trace_id`，runtime context 使用同一 ID；其它调用方业务元数据保留，原 metadata 对象不变。
3. 每次 `next(inner)` 单独绑定/恢复，不让 ContextVar token 跨越 yield。
4. 提前关闭时 `inner.close()` 的 finally 路径也绑定该轮 ID。即使其它 Context 触发清理或清理抛错，仍恢复关闭方原有 context。
5. 交错的无父级 scope 流各自独立；已有父级 scope 可显式关联；未开始的流 close 不启动工作。

## 上一轮最先发现的五项阻塞

- 员工删除 blocking-IO 回归缺少已有草稿 CAS revision。测试现通过 off-loop 真实读取获取 reviewed revision，再调用真实删除接口；生产 428/409 规则未改变。
- 跨进程发布测试原来只有 30 秒解释器启动预算；本机单独导入该模块实测 159.39 秒，15 秒栈快照位于 Python 模块读取/导入而非 publication lock。
- 调整测试为独立有界启动阶段（180 秒）和竞争阶段（保持 30 秒）；子进程先完成真实快照读取，必须等父进程统一放行，不再忽略 `Event.wait()` 超时。新增未放行绝不发布的反例，并检查所有竞争进程正常退出。生产 5 秒锁等待和单一成功者 CAS 断言未放宽。
- 删除/发布/文件与 SQL 草稿 API 联合回归首轮：62 通过，含真实 spawn 双进程单一成功者、缺版本拒绝删除、保留他人及广场定义。新增未放行反例在上述独立复核中通过。
- 三项渠道凭据文件权限断言在 Windows 实测 0666、预期 POSIX 0600。原测试移到 `backend/tests/blocking_io/test_channel_runtime_config_permissions.py`，保留全部实质断言，无 skip 或阈值放宽；原路由 IO 测试仍独立保留。
- Linux 权限专测：**3 通过，1.33 秒**。使用本地已有 `deerflow.local/multiworker-r4-r7-compat-base:local`（镜像 ID `bfd4e32cb047`）内 Python 3.12.13 / pytest，仅作依赖运行器；被测模块通过只读挂载使用当前 checkout，而不是镜像内旧代码。禁网、1 CPU、1GiB、只读 rootfs、无 capabilities、uid 1000；pytest 临时数据在容器原生 `/tmp` tmpfs，不在 Windows bind mount。
- 权限专测命令采用 `--noconftest -p no:cacheprovider --basetemp=/tmp/pytest`，仅证明三个文件权限契约，不声称覆盖 Blockbuster async IO gate。正常全套收集仍加载原 blocking_io conftest，Windows 上的 POSIX mode 断言仍不能算通过。
- Linux 联合回归：**65 通过，576.49 秒**，覆盖 `blocking_io/test_agents_router.py`、`blocking_io/test_channel_runtime_config_store.py`、`test_agent_publication_versions.py` 和 `test_agent_draft_api.py`，加载正常 conftest / Blockbuster；真实 spawn + Linux flock 单一成功者断言通过。与独立权限专测合计 68 个不重叠用例。容器禁网、1 CPU、3GiB、uid 1000、只读代码；声明为 amd64 本地临时文件系统验证，不是 ARM64/NFS 生产验收。
- 原全套命令带 `--maxfail=5`，所以这五项是最先遇到的失败，不是全部剩余缺陷。
