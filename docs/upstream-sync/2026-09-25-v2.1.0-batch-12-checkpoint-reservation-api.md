# v2.1.0 批次 12：检查点互斥上层接通

## 来源及实现

目标仍为官方 `345f08be00c8a9495079b732a39b46aa9af1584e`，适配 #4437 `3c8b82c5941c931ce7b9e3c5dacc34dfd66a81e3`。在批次 10 存储和批次 11 原子回收基础上，接通 RunManager reservation、续租失权处理、Gateway service 和 goal/compact/state 写入入口。

- 经过原有权限校验后，对完整检查点读/合并/写操作取得持久化互斥；标题同步也在此范围。其他 worker 活跃时返回 409，不能用 interrupt/rollback 抢占检查点写入。
- 保留企业 owner 解析、pending 启动屏障和持久化取消；释放使用取得 reservation 时的 owner，不读取变化后的 ambient user。
- 取消请求释放 reservation；删除失败保留持久化证据供过期回收。晚到的续租失败须重查当前拥有的活动任务，不得取消已释放后继续处理请求的 task。
- 内部操作不进入普通历史、批量 run 读取、regenerate、token 和 Console 统计；孤儿扫描仍处理内部操作，但不将它们报告为用户 run。
- 前端重命名在失败时保留弹窗和输入，展示错误；只有成功回调才关闭，不自动重试。React 技能用于维持事件回调内的状态更新，不增加副作用监听。
