## Behavior

- Read `config.yaml` with `utf-8-sig`, preserving ordinary UTF-8 behavior while
  removing only an optional leading byte-order mark.
- Detect `langchain_ollama` only from a model entry's direct `use` field.
- Support both indented model lists and the indentless list emitted by the setup
  wizard, without treating nested fallback or thinking-mode providers as the
  primary model provider.
- Expose the application-level `ollama` extra as a forwarding dependency on
  `deerflow-harness[ollama]`, keeping the lock file consistent.

## Enterprise adaptation

The detector keeps the enterprise Browser field-order parser introduced in
Batch 20. Existing PostgreSQL, Redis, Discord, and Browser detection semantics
are unchanged. Earlier enterprise batches already contain the official Sandbox
image BOM fix (`53f2a73d2`) and uploaded-document summary BOM fix
(`990c7b95a`), so those changes were audited but not duplicated.
