# 批次 60：实际执行准入与独立任务标识

承接批次59，基于固定官方 v2.1.0 的 execute / execute_async / capacity 接线，
仅局部替换调度路径，不覆盖企业版执行主体。

## 实现

- 同步及后台执行都进入已有持久隔离事件循环，共用进程控制器；删除旧
  ThreadPoolExecutor 的无界等待队列。排队保持 PENDING，取得名额才记录
  RUNNING/started_at，并在流关闭和沙箱执行租约清理完成后归还名额。
- Gateway 与 Embedded Client 使用启动配置快照；PPT Runner 不启动此原生
  子代理准入配置。相同初始化不重建活跃队列，重载不能暗中扩大进程名额。
- 外部 provider tool-call ID 仅作相关性字段；后台 registry 使用独立 UUID，
  避免不同用户/线程相同调用 ID 覆盖结果或互相取消。
- 后台 asyncio 总超时包括排队；容量拒绝/排队超时标记 admission_failure。
  提交失败撤销 registry，取消在锁外调用 future.cancel，避免回调死锁。
- 本地增强：协程首条指令执行前取消也必须持久化终态，不能遗留 PENDING；
  setup 前及取得名额后重查取消/终态。BaseException 提交失败也撤销登记。
- 保留企业回执、员工/知识身份、审计桥、流关闭和租约实现。补取消/超时
  尚未输出下一状态块时的 token callback 快照，避免已发生用量丢失。
