## 已实现的局部契约

1. `TraceMiddleware` 不依赖 `logging.enhance.enabled`；有效 `X-Trace-Id` 可用于客户端关联，无效或缺失值重新生成。保留旧 `enabled` 参数作为无效兼容参数。
2. 响应开始时写 header，不缓冲 SSE；响应开始前未处理异常返回带 ID 的普通 500 后重新抛出，保持异常日志。流中失败不发送第二个响应头。
3. 沿用现有 CORS 来源白名单，仅暴露 `X-Trace-Id` / `Content-Location`。未处理异常的兜底 500 仍对跨域浏览器不透明，与官方一致；不复制一套 CORS 授权策略。
4. `start_run` 的外层为每次准入建立/继承有界 trace context，使通过同一入口的后台调用不污染长期轮询任务。HTTP 请求的 worker 继承准入 context。
5. 服务端在准入边界覆盖 `metadata.deerflow_trace_id`，运行记录和 live config 使用同一 ID。复制合并，不修改请求原对象；新建线程不保存 run-scoped ID。
6. worker 忽略调用者 context 中的 trace，HTTP ambient trace 优先于 config metadata；保持其它身份和企业上下文规则。
7. 请求配置回显省略 context/metadata 中的伪造 trace，保留普通业务字段与现有 secret 清理。历史 API 返回只改副本，不重写原记录。

企业差异：保留当前 `start_run` 权限/员工授权次序，通过薄 scope wrapper 适配，不引入上游服务层其它尚未完成的依赖。保留直接内部 worker 调用的合法 metadata fallback；尚不能宣称所有非 HTTP 消费者都实现 ContextVar 唯一权威。
