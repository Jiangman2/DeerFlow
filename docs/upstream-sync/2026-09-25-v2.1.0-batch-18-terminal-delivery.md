## 生命周期与企业适配

1. Journal 在可失败/可取消的 startup 前创建，但 early failure 不覆盖历史完成统计。
2. worker 先 flush 工具记录、写一份 delivery，再结束持久运行。goal continuation 不重复生成终态回执。人工等待保留 `awaiting_human_input`，END 留到收尾。
3. 终态的内存意图与持久状态分离；数据库仍保持 active，直到最后的 duration checkpoint 写完，避免对端提前允许历史修改。先写 finalizing progress，再 CAS 仲裁取消与结果。
4. 补测发现官方片段直接移植会留下两个企业边界缺口：暂存 success 后不续租、同进程单 worker 取消被误判不可取消。增加仅进程内的 `terminal_status_pending`，保留续租/准入/取消，确认落盘后清除；无数据库列或迁移变化。它不能延长已过期的租约。
5. 回执写入或 Journal flush 期间发生失权，停止后续状态/完成/回调写入，仍结束 stream 并解绑 Journal。取消回滚只执行一次，保持沙箱执行租约和 WeKnora 上下文清理。
6. 接管 CAS 失败（并发续租、完成、删除）绝不补零回执；内部 checkpoint reservation 不生成用户交付记录。已有真实回执优先，event store 故障不撤销孤儿终态。
7. 恢复写入绑定持久 run owner，独立 Context 避免 Bob 触发 Alice 的恢复时写成 Bob；NULL 归属不被重新认领。Gateway 注入同一 event store，独立 PPT runner 的启动全局回收禁用保持不变。
