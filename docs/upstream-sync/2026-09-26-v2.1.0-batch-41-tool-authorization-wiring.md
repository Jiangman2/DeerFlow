# 批次 41：工具装配与执行双层授权

接通锁定官方 v2.1 的工具授权链路（#4370 后续最终行为），保留企业筛选与
批次 39 的线程绑定 Skill。没有启用生产 authorization 或改变角色策略。

## 实现

- 主代理普通/bootstrap、子代理、DeerFlowClient 在 deferred MCP catalog
  建立之前过滤工具；describe_skill、主代理后加入的记忆工具也先过授权。
- 同一构建实例传给执行时 GuardrailAuthorizationAdapter；显式 Guardrail
  独立存在且在内层，授权拒绝不触发外部策略调用。仅具体已过滤 catalog
  生成的 tool_search 获得基础设施例外，不根据静态配置放行同名工具。
- 子代理在线程卸载 Provider 类发现，但在子执行循环构造实例；保留企业
  发布快照、业务线程、员工工具/知识/data-lake 范围和 execution lease。
- 嵌入客户端传递显式进程内身份至两层；开启授权时每 run 重建 graph，避免
  外部策略/角色/attributes 变化复用旧工具权限；关闭时保留缓存行为。
- 真实 LangChain create_agent 暴露官方示例仅检查列表未覆盖的兼容点：
  两个 GuardrailMiddleware 同名导致构建拒绝。给授权实例独立 name，复用
  原执行/异常/审计代码；普通 guardrail 的默认名称不变，未另造权限引擎。
