# v2.1.0 批次 10：检查点互斥的存储前置（上层尚未接通）

## 来源与边界

固定 `v2.1.0` / `345f08be00c8a9495079b732a39b46aa9af1584e`，适配 #4437 / `3c8b82c5941c931ce7b9e3c5dacc34dfd66a81e3` 的存储部分。官方 0008 与企业已存在的 0008 冲突，新增企业 revision `0021_thread_operation_kind`，接在 `0020_run_cancel_request` 后。没有覆盖旧 migration。

本批仅包含存储准入原语、枚举、模型与迁移。RunManager 的 reservation context、API goal/compact/state 入口、控制台及页面冲突提示尚未接通，因此不能宣称“检查点跨 worker 互斥已完成”，也不启用新部署拓扑。

## 实现

- `operation_kind` 区分 `run` / `checkpoint_write`，非空服务端默认 `run`，老记录和旧 SQL 插入保持原有含义。
- SQL 与内存实现共享 `create_thread_operation_atomic`，旧 `create_run_atomic` 保留普通 run 兼容别名；第三方仅实现旧方法时不能假装支持内部操作。
- 使用原 `uq_runs_thread_active`，不新建一套锁表；有效/无租约 checkpoint 写不能被 interrupt/rollback 替换，真正过期租约可接管但保留其记录。
- 内部操作不进入存储层历史、批量历史、regenerate 来源、pending 派发和 token 总计；lease 扫描仍可找到它们。
- 保留已有企业取消意图、owner 解析与 token 用户筛选；补丁不能用官方旧版本覆盖这些企业差异。
- 企业收紧 release：只允许删除指定 captured owner 的内部操作，不能顺手删除普通 run，ambient user 改变不影响正确释放。
- 企业降级保护：存在任何内部操作记录时拒绝丢弃 discriminator，防止旧版本误解释成普通运行；不静默清理孤儿证据。无内部操作时可在隔离测试库验证 schema 往返。

## 验证

首轮存储/迁移/owner/RunRepository 回归 **123 项通过**（30.72 秒）。新测试覆盖 memory、真实 SQLite、真实 loopback PostgreSQL：双向准入竞争、同 worker/跨 worker、interrupt/rollback、有效/空/过期租约、隐藏内部统计、显式 owner 释放与旧扩展接口。

扩大到此前配置、数据库、调度、运行生命周期和渠道范围后，**1340 项通过、5 warnings、无跳过**（202.38 秒）；该数字是在后续 orphan CAS 修复之前记录，不把它冒充修复后的最终回归。

真实旧 SQLite 链保留双用户中文员工、未知字段、线程和运行内容；重复升级不修改历史，旧列写入仍默认普通 run，取消意图不丢失，有内部记录时降级拒绝且保留数据。现有“到 head”测试断言推进到 0021，专门测试 0020 的 revision 断言保持不变。真实 PostgreSQL schema 的 0019→head 验证也检查新列。
