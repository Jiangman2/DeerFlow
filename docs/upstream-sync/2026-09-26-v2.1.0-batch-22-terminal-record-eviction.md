# v2.1.0 批次 22：终态记录安全延迟清理

对齐 #5112 `45adb8fbb5a9d21a93cec160231835d58f432ab7` 的 300 秒 RunManager cleanup，在批次 21 的引用释放后以空 Context 调度，正常完成、hook cancellation、END failure 均覆盖。

企业适配：不能照搬无条件 pop。清理前后两次检查同一对象、终态、无活跃 task、无 finalizing / terminal_status_pending；锁外使用 captured user_id 查询 store，再核对 run/thread/owner/operation kind 和终态。存储不可用、缺行、未终态或身份不符时保留记录；peer 的不同终态不被改写。没有 backing store 时保留历史。这里只删除本地索引引用，不删除数据库或 MemoryRunStore 历史。

保守边界：这是一轮延迟清理，不会在存储失败后反复无限重试；未确认记录可能继续留在内存，不能宣称全局内存已有硬上限。
