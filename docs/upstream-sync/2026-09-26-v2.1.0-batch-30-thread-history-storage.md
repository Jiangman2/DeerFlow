# v2.1.0 批次 30：线程历史清理存储前置

官方依据：固定 v2.1.0 中 #5535（`26437b61d0b402ddaee4ef943e0fd84635d641e3`）的最终删除语义。本批完成存储层，不将 HTTP 删除入口或永久删除墓碑宣称已完成。

## 实现及企业边界

- DB 事件删除与写入取得同一进程内线程锁及 PostgreSQL 事务 advisory lock，再计数、删除、提交。正常提交才解除 thread lock pin；失败、取消保留正确锁生命周期。
- `delete_by_thread` / `delete_by_run` 保留 AUTO、显式 owner、显式 None 三态授权。memory / JSONL 的 thread-keyed 开发接口接受兼容参数，不冒称具有数据库 owner 隔离。
- Run 历史清理仅删除 `operation_kind=run`，当前内部操作 reservation 必须存活到准入保护退出；保留其他 owner、其他 thread 及 memory thread 索引一致性。
- Feedback 清理显式限定 owner / thread。它清理现有记录，不承诺阻止删除后新的已准入 feedback 写入。
- 不加数据库迁移，不开启生产新后端。不把事件锁视作永久墓碑：删除提交后，一个新生命周期仍可写入。

## 验证

- 新增真实存储、三态 owner、锁竞争、事务回滚、锁等待/事务中取消用例。PostgreSQL 测试持有另一个连接的相同 advisory lock，并查询 `pg_locks` 确认实际等待，避免只凭 sleep 推断互斥。
- 本机临时 PostgreSQL 16：仅 loopback 随机端口、合成凭据、唯一临时 schema、tmpfs 数据、限制资源。未读取或连接生产数据。
- Windows 联合回归 **315 通过、无跳过，47.76s**：线程历史、事件、run repository、feedback、内部操作、JSONL 阻塞 I/O、lease、journal、delivery 和 PPT 发布回执。
- Linux `--network none` / 非 root / 源码只读回归 **106 通过、14 跳过，41.87s**；跳过项均需 loopback PostgreSQL，已在前一组真实 PostgreSQL 验证中执行。两组有重叠，不累计为总测试数量。
- Scoped Ruff / format / diff whitespace 检查通过。使用 PostgreSQL skill 的短事务及 advisory-lock 指引；未加入无关索引或配置更改。
