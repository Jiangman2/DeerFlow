# v2.1.0 批次 34：Command 包装工具回执的失败语义

官方来源：#4977，`8eda71fd978b4dc4b26843fe995407f09f4aa87e`；已对照锁定 v2.1.0 中相同包装/状态行为。

## 实现与保留边界

- Error middleware 的同步/异步入口传递当前 tool-call ID，遍历 Command 中 single/list/tuple ToolMessage；只归一化匹配回执，保留 goto/resume、artifacts、其他 update 字段及其他调用消息。
- 子代理 `failed/cancelled/timed_out/polling_timed_out` 优先于显示文本，即使 LangGraph ToolMessage.status 仍为默认 success，也产生 error 元数据；已由生产者盖章的 metadata 不被替换。
- Progress middleware 从同一匹配回执更新 warn/block/recover，而不是无条件忽略 Command。
- 保留企业 Bash project-repair 例外：脚本/项目配置失败可修复，不把通用 Bash 永久关闭；基础设施 exception 的 stop 仍生效。task 的默认 progress exemption 不变。
- 兼容性加固：先验证 subagent_status 是字符串，避免历史损坏的 list/dict 触发 set membership TypeError；未知状态仍用原有内容语义，不凭空改写成成功/失败。
