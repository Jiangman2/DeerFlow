# v2.1.0 批次 05：运行 owner 一致性

日期：2026-09-25。仅本地适配，未构建或部署。

## 来源和实现

官方 #5401 `6f81daefff2035d76d41e45d021626f022885372`；以固定 v2.1.0 最终行为为依据。

已核实本地差异：HTTP/内部准入未显式提供 user_id 时，SQL 持久层会解析当前用户，RunManager 的本地记录却保留 None。这会让按 owner 过滤的本地查询漏掉记录，也会破坏后续幂等复用的 owner 比较。

`RunManager.create` 和 `create_or_reject` 现于登记/持久化前捕获当前用户：

- 显式可信 owner 优先，不用环境用户替换定时任务 owner。
- 隐式 owner 读取已认证 ContextVar，UUID 在边界转为字符串。
- 无用户 context 不发明 `default` owner；SQL 原有缺身份拒绝语义保持。
- 不改变读接口授权、不扩大管理员权限、不共享用户数据、不新增 schema。
