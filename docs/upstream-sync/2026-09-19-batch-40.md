# Upstream Sync Batch 40 — Durable Discord Thread Mappings

## Scope

- Enterprise branch start: `7701aa6db`
- Recovery tag: `enterprise-pre-upstream-batch40-20260919`
- Official behavior adapted from `1d8b6ead0`.

## Behavior

- Discord shutdown performs a best-effort final persistence pass for the
  current channel-to-thread mapping, closing the window between the synchronous
  in-memory update and its normal offloaded filesystem write.
- The final flush is enabled only after the persisted mapping file has been
  loaded successfully, including the valid first-start case where the file is
  absent.
- If startup exits before the load, or the stored JSON cannot be read, a later
  `stop()` cannot overwrite the previous mapping file with an empty snapshot.

## Enterprise adaptation

The change is applied to the existing enterprise Discord lifecycle without
altering channel identity, thread creation, queue admission, outbound delivery,
or the shared channel store. The mapping file and its current atomicity model
remain unchanged.

Nearby official Telegram rich-message selection (`a922efe14`) is not imported:
this enterprise branch does not contain the Rich Message transport on which
that correction depends. Assistant-search pagination validation (`22ae3d0e9`)
was also audited and is already present in the current source and tests.
