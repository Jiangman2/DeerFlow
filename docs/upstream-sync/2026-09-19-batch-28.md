# Upstream Sync Batch 28 — Safe Host-Path Masking

## Scope

- Enterprise branch start: `fb886bea9`
- Recovery tag: `enterprise-pre-upstream-batch28-20260919`
- Official behavior adapted from:
  - sandbox portion of `45adb8fbb` — avoid retaining per-thread roots in the
    process-global regular-expression cache
  - `d5ae3882b` — reverse-resolve forward-slash spellings of Windows host paths
  - `1b9667ea0` — mask every host path in a colon-joined list

## Behavior

- LocalSandbox now scans high-cardinality thread roots directly instead of
  compiling one reverse-output expression per sandbox.
- Windows host paths emitted with forward slashes map back to their virtual
  `/mnt/...` paths.
- PATH/PYTHONPATH-style colon-joined output masks every matching host path,
  rather than consuming later entries as part of the first match.
- A symlink located inside a mount no longer exposes an outside target's host
  path. A target inside another mapped mount still resolves to that mount.

## Verification

- Combined path-pattern, LocalSandbox mount/path, search-tool, E2B, BoxLite,
  and tool-security regression suite:
  `369 passed, 13 skipped, 6 deselected`.
- The six deselections are pre-existing Windows-host assumptions: one POSIX
  `/bin/sh` execution test, three assertions that require POSIX path spelling,
  one environment-dependent Skill extension test, and one symlink-privilege
  test.
- Three previously deselected Windows reverse-path tests now pass, including
  agent-written file reads, write/read round trips, and workspace glob output.
- Targeted Ruff checks and `git diff --check` pass.
