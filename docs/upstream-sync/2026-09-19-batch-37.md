## Behavior

- A delete can retire a thread without replacing the lock still referenced by
  an admitted holder or waiter.
- A later writer resolves the same live lock generation during the
  `asyncio.Lock.release()` handoff window instead of running concurrently on a
  fresh lock and racing event sequence assignment.
- Database-backed stores retain one pinned lock for each live thread and drop
  the pin on deletion. Weak ownership releases the retired generation after
  outstanding users drain.
- JSONL stores use weak lock ownership, avoiding an unbounded registry of
  historical thread IDs while preserving queued mutation ordering.
