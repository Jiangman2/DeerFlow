## 实现与企业差异

1. DatabaseConfig 和旧 CheckpointerConfig 增加 schema 校验：只接受不超过 63 字节的 ASCII 小写标识符，拒绝空白、换行、引号、注入和大小写歧义。连接参数构造边界也再次校验。
2. ORM asyncpg、Alembic 独立连接、同步/异步 LangGraph checkpoint/Store 均传递目标 schema；首次创建、重新启动和自动创建数据库后的重试保持一致。
3. 保留企业 `drained_async_context`，没有用上游整文件覆盖取消/关闭修复。
4. 企业同步员工存储通过 `app_sync_sqlalchemy_url` 注入 psycopg options，保留驱动、凭据及已有 options；schema 进入原有 URL 缓存键，防止跨 schema 复用同一员工连接池。不改写已有员工 CRUD/共享逻辑。
5. 旧 checkpointer 区块继续只覆盖 LangGraph 后端，不能静默覆盖 ORM/员工配置。
6. `config.example.yaml` 版本 31→32，增加仅注释形式的可选配置和数据迁移警告；没有修改本机或生产 config.yaml。数据库配置仍要求所有相关进程重启，不做部分 singleton 热切换。
7. 修正两处测试夹具：未配置 checkpoint 测试同时 mock 实际导入位置，避免读取开发者私有配置；临时 `_tmp_test` 使用独立 MetaData，不污染后续迁移表集合断言。

## 限制与下一依赖

这是局部联合回归，不是全仓库或生产验收。自定义 schema 不是租户授权机制；本批不自动移动任何已有表。若部署以后要切换 schema，必须另行清点所有企业表、LangGraph 表和 alembic_version，验证备份恢复并授权迁移。
