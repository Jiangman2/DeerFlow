# v2.1.0 批次 28：Linux 离线回归与 MIME 防护可移植性

本批是全套回归发现的企业适配/测试隔离，不冒称整个官方 PR 集合完成。

## 首轮发现

Linux `CI=1` 全套测试设置 `--maxfail=8`，在 1042 通过、8 失败、6 跳过后停止（132.40s）。此前 Windows 定向通过不代表这次 Linux 全绿。

1. 精简 Linux 的系统 MIME 表没有正确识别 XHTML，普通 artifact 与 `.skill` 成员未按已有企业规则强制下载：实际兼容缺陷。
2. 配置重载测试在 legacy memory checkpointer 移除后使用默认 SQLite 相对目录；只读源码挂载不可写：测试隔离缺陷。
3. 浏览器/Browserless mock transport 测试仍做公网 DNS，network-none 环境不能解析：测试外部依赖，不是放宽 SSRF 的理由。

## 修复及证据

- 增加 active suffix MIME floor（HTML/XHTML/SVG/XML/XSL/RDF/RSS/Atom），无论系统 MIME 缺失或误报 text/plain 都只收紧到 attachment；其他 `+xml`、PDF 内容检查、原始上传规则不变。24 个强制 MIME 缺失/误报用例先失败，再通过。
- SQLite reload 测试显式将测试库放到 tmp_path，仍验证旧 singleton 被真正替换，不改生产默认配置。
- Browserless/Browser 单测仅为已知合成公网域名 stub DNS，继续执行真实 SSRF validator；私网、metadata、scheme 测试保留。错误分支增加真实 fake client 被调用及原始错误断言，避免被 DNS 错误假通过。
- Linux 续跑发现 readabilipy 的 JS parser 在该依赖镜像中尝试隐式 `npm install`。检查容器身份后停止这个本任务临时容器；网络始终关闭，宿主仓库只读。Browserless transport 单测改为显式注入 article parser，未更改真实 ReadabilityExtractor。**真实离线 parser 依赖闭包仍需候选镜像验证，不能以 mock 宣称通过。**
- Windows 相关 5 个模块：204 通过，11.07s（parser fixture 最终隔离后的复验另记）。
- Linux 相关 5 模块加批次 26–27：297 通过、1 跳过，75.16s；唯一跳过因依赖镜像无 Playwright，Windows 批次 25 已独立做本地 Chromium 用例，但不代替 Linux 浏览器验收。
- scoped Ruff 通过；既有 `test_browser_automation.py` 的 UP017 datetime 写法单独忽略，不把无关代码改动夹入本批。

使用本机依赖镜像 `deerflow.local/multiworker-r4-r7-compat-base:local`，`--pull never --network none --read-only --user 1000:1000 --cpus 1 --memory 4g --pids-limit 128 --cap-drop ALL --security-opt no-new-privileges`；仅当前源码只读挂载 + /tmp tmpfs。无生产连接、无宿主数据挂载。
