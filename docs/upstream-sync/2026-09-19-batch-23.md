# Upstream Sync Batch 23 — AIO SDK Compatibility Floor

## Scope

- Enterprise branch start: `7a005f3ebbaf`
- Recovery tag: `enterprise-pre-upstream-batch23-20260919`
- Official baseline aligned:
  - `agent-sandbox>=0.0.30` in the current upstream harness

## Behavior

- Require `agent-sandbox` 0.0.30 or newer when resolving a fresh backend
  environment.
- Keep the already locked 0.0.30 artifact and hashes unchanged; this batch
  prevents a future environment rebuild from legally selecting an older SDK.
- Preserve the enterprise AIO provider, deterministic user/thread Sandbox
  identity, warm pool, Provisioner, NFS mounts, and PPT Runner execution leases.

## Semantic audit of adjacent upstream fixes

- Official MCP bare-filename literal replacement (`796ca28f5`) is already
  present in enterprise commit `0584f35411`, including platform-independent
  backslash and unknown-regex-escape regressions. It was not duplicated.
- Official async rebind release draining (`4889f61f1`) targets the upstream
  `SandboxLeaseManager.retain_async` architecture. This enterprise branch does
  not contain that rebind path: it serializes deterministic Sandbox discovery
  and creation with per-user/thread locks plus a cross-process file lock, and
  protects destruction with the separate shared/exclusive execution lease used
  by Gateway and PPT Runner. Importing the upstream lease manager would create a
  second lifecycle authority, so the patch is not applicable here.
- AIO subagent shell-session sizing (`d8d110c63`) remains intentionally deferred
  to a dedicated batch because it changes Gateway, provider, Provisioner, and
  runtime-capacity contracts together.

- The locked `agent-sandbox` package remains exactly 0.0.30.

- Targeted AIO provider, remote backend, warm-pool, and Provisioner tests cover

## Operational impact

No production workload, database, Kubernetes manifest, WeKnora, SkillHub, or
Sandbox image is changed. The next backend environment build refuses
`agent-sandbox` versions older than 0.0.30. Production AIO Browser and MCP
Browser remain disabled by the enterprise runtime policy.
