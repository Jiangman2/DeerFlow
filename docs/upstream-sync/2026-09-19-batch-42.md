# Upstream Sync Batch 42 — Reconnect Input Hydration

## Scope

- Enterprise branch start: `d156e5aa8`
- Recovery tag: `enterprise-pre-upstream-batch42-20260919`
- Official behavior selectively adapted from `d1f77fc1f`.

## Behavior

- Reconnecting to an active run now reads the original submitted input from
  the persisted run record before replaying incremental AI and tool events.
- The submitted messages are merged into the latest durable thread values and
  de-duplicated by message id, preventing a refresh during the checkpoint
  window from temporarily losing the user's latest message.
- If run metadata or durable state cannot be read, reconnect retains its
  previous fail-open behavior and joins the stream normally.
- Terminal-run short-circuiting remains intact, and reconnect cancellation is
  propagated through both the run and state reads.

## Enterprise adaptation

The official commit also modifies its newer stream replay-gap recovery layer,
which is not present in this enterprise branch. Only the self-contained input
hydration behavior is imported. It is integrated with both the ordinary
Gateway runtime and the enterprise isolated PPT Runner runtime; no request is
sent to the wrong checkpoint namespace.

The enterprise `threads.getState` wrapper now preserves the SDK's checkpoint
and request-options parameters so abort signals are not lost while routing to
the PPT Runner.
