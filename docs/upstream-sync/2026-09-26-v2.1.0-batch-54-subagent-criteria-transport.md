## 实现

- report_contract 对齐固定 tag：条件最多 20 条、每条 500 字符，丢弃非字符串、
  空白和伪造的框架标签；截断前后都清洗，规范化幂等。
- task 工具增加可选 acceptance_criteria；Executor 复制并规范化，既有位置参数
  及不传条件时的 executor kwargs 保持兼容。
- 可信 SystemMessage 只指向条件清单，条件原文放在 HumanMessage，不将子任务
  输入提升为系统指令。加入 report_contract / acceptance_criteria 标签防注入。
- lead prompt 增加验收条件、真实交付句柄、引用交叉核对和矛盾复查要求；关闭
  receipts 时不声称引用核对可用。保留企业显式并行 / Ultra 首轮委托规则。
- 修正 LangChain Google docstring 解析：多行参数说明中的 `Prefer file:` 曾被
  解析为不存在的参数，改为单行说明并通过真实模块加载/测试收集验证。

尚未实现确定性 acceptance checker、对应结构化 verdict、batch_task 接线或
judge；此时传入条件不等于宿主已经验证满足。lead 完整的成本收益/单专家委托
策略仍需单独对照最终官方行为，不能以本批提示词片段替代整体验收。
