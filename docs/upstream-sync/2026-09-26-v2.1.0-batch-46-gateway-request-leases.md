# 批次 46：Gateway 上传请求租约与取消清理

续接批次 45；适配锁定官方 #5134 的 request holder 最终行为，复用已有企业
`acquire_sandbox_client_lease` / `SandboxClientLease` / lease manager，未复制
第二套引用计数，也没有接管专用 PPT Runner 的沙箱生命周期。

- 单请求 lazy acquire、唯一 holder；upload-only 使用 release_on_last=false。
  没有沙箱操作不分配 holder。上传同步和独立旧 DOC fallback 共享本请求的
  client；fallback 复用前再次授权。关闭后的 session 不能再次 acquire/run。
- 将上传事务放在 async context 生命周期内。解析、体积校验、同步、client
  丢失等失败都清理 holder。保留主机上传回滚、required parse 和早期输入限制。
- 沙箱阻塞命令/复制/下载及 DOC 临时目录清理走既有 cancellation-draining
  lease.run_sync。另一个 agent 完成时若请求仍在用 client，其 release 延迟到
  最后一个 holder 清理；单纯上传完成不主动 park。
- 转换取消后若清理期间再次取消，实际 cleanup worker 完成前不释放 holder，
  保留第一次取消原因。正常 provider 故障仍保留旧 DOC 可选回退的失败语义，
  GraphBubbleUp 和取消不能被吞成“没有转换结果”。

session、实际上传 worker 的正常/迟到异常 + 重复取消、转换/复制失败、client

无跳过，36.08s**。Linux 覆盖 Windows 缺少符号链接权限的 3 项。
另有批次 45 的 auth middleware/type-system 六模块 Windows 354/3 skip、
Linux 357 全通过；计数重叠，不相加。七个相关文件 Ruff check/format 通过，

验收，也不是整个文件上传事务在任意机器断电下的原子性保证。
