## Enterprise adaptation

- Keep the enterprise `start_channel_service(app_config)` signature and channel
  configuration path.
- Publish the singleton before channel startup as before, but retain the exact
  service identity for guarded rollback.
- On startup failure or cancellation, drain `ChannelService.stop()` before the
  original exception or cancellation propagates.
- Clear the singleton only after that rollback succeeds; retain it if cleanup
  itself fails so operators do not mistake leaked resources for a stopped
  service.
- Add a reusable `await_drained()` helper only; do not import upstream Projects
  code or broader lifecycle refactors.
