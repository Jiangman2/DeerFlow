## 闭合的本地契约

1. `resolve_trace_id` 只接收宿主维护的 carrier；非法值不能进日志/HTTP 头。无 carrier 时继承或建立当前 scope 的 id，不把任意 runnable metadata 当作权威。
2. MemoryMiddleware 在排队前捕获 run id；用户归属及选定 WeKnora 知识域不写入普通持久记忆的原规则保持。已有线程回调为更新过程绑定/恢复该 id，成功和异常均不污染复用线程。
3. 子代理在创建时捕获父 scope，在实际执行线程/事件循环中恢复；执行失败、取消、sandbox lease cleanup 都在同一 scope。原短 `trace_id` 字段不等同于请求级 `deerflow_trace_id`。
4. Worker 的初始化、模型/工具流、finalization、派生异步 cleanup 具有同一 id；直接 harness 调用也有有界作用域。调用方 metadata 里的保留 trace 被覆盖，但普通业务 metadata、Langfuse session/user override 保留。
5. 嵌入式同步接口在已有事件循环下交给辅助线程执行时，复制当前 ContextVars；新线程内修改不回写调用方。真实线程测试覆盖成功、异常、取消。
6. Langfuse **已启用时**，metadata builder 在缺少 carrier/context 时仍产生稳定关联 id；未启用时保持空结果且不制造该 builder 自己的 id。此项不是外部遥测上线配置。
