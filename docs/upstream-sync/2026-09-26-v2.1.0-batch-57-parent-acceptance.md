## 实现

- 普通 task 仅对 completed（含有产出的 capped）执行确定性检查，将逐项
  checklist 加入模型结果，并在结构化 metadata 和 checkpoint 委托台账中
  保留经严格校验的 verdict。失败、取消、超时不附加“完成验收”。
- 保持 completed 是执行终止而非任务验收。混合结果分别标记 holds / does
  not hold / UNVERIFIED，不改变原始状态、cap、用量或子代理完整报告摘要。
- 企业差异：文件检查进入异步 sandbox 授权，并在获取客户端前验证员工授权，
  获取后验证挂载。独立 holder 和私有 runtime 不覆盖父任务的租约或 shell
  scope。共享既有租约管理器；获取/校验/探测/读取被重复取消时先 drain，
  再释放 holder，不使后台 IO 越过清理边界。
- 只有限定 workspace / outputs 内的文件条件才初始化 provider；纯命令、
  不可判定或越界文件条件不触发 provider / 策略发现。策略缺失、拒绝、撤销、
  挂载或 provider 错误使文件证据保持 unknown，不伪称文件不存在；同一清单
  的有效命令证据仍可核对。日志不输出 provider 错误内容。
- 外部运行输入和 state 写入剥离 subagent_acceptance_verdict，保留可信内部
  重放；读写两侧校验聚合与叶子一致性。台账摘要截断不会丢失独立 verdict。
- task_completed 事件在父层检查之后发出，取消中的检查不先发布完成事件。
