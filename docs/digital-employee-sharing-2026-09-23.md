## 已确认的问题

2026-09-24 补齐一个真实前端缺口：原 Slash 候选仍读调用者个人 `/skills`，已新增员工专属只读目录并接入员工聊天输入框。已有对话按服务端线程凭据读取固定发布版本，目录按用户/员工/来源/线程隔离；不安装、不暴露路径或源码，撤权/损坏不回退个人目录。普通聊天维持原目录。Windows/Linux 的目录及相关授权 API 各 10 项通过；浏览器桌面/手机加版本与失效场景 5 项通过。页面首次补测因遗漏员工详情 mock 和既有动态标题断言失败，修正夹具/标题身份断言后通过；不改变生产逻辑来迎合断言。React/shadcn 既有输入框与 Alert 被复用。README 本轮再次因工具写入失败未同步，原文件保留；模块指南与本审计已同步。

25 模块生产组合的扩大运行回归已结束：258 通过、1 跳过，实际加载覆盖门禁通过；依赖仍本地。为关闭精确依赖缺口，补采工具增加真正的上下文压缩、输入框及新模块存在性白名单。补采/合并先新增测试得到 8 失败，再实现；Windows 符号链接用例由无网络只读 Linux 容器实际执行，未把跳过当通过。当前仍无可安全上生产的最终包。

Gateway 精确组合范围后续已扩展到 25 个模块：主 Agent、子任务、Slash Skill、冻结目录及沙箱挂载。混合修改的函数使用唯一代码块锚点，保留生产工具/密钥协议、流处理、锁与回收逻辑，不夹带 Multiworker。组合器及不相关代码保留检查 19 项通过；扩大实际运行回归单独记录，不能沿用原 8 模块结果宣称 25 模块全通过。这里 Slash 指员工对话中的 `/技能名`，不是新增 `/员工名` 选择入口。

现有广场发布只复制员工配置、SOUL 和头像，Skill 配置仍然是一组名称。运行侧再按调用者自己的启用目录解析这些名称，因而创建者的私有 Skill 不存在于调用者目录时会丢失；调用者有同名 Skill 时也可能指向不同内容。

另外，原先个人员工、团队员工和旧版共享员工有同名回退，前端聊天仅传 `agent_name`；仅补复制文件不能解决来源歧义。本次已增加显式 `agent_source=personal|team|legacy` 的精确解析：请求指定来源不存在时不回退到其他同名员工，共享员工上下文不能编辑同名个人配置。省略来源的旧入口首次按原兼容优先级选择，若选中团队发布便固定版本，之后创建同名个人员工不改变该对话的绑定。全部渠道/定时/子任务与显式换版入口仍需验收，来源字段本身不是跨用户资源授权。

知识选择当前依赖调用者的 WeKnora 身份与可见资源，不存在“发布一个员工就能替大家使用创建者所有知识”的可靠授权机制。不能通过注入发布者通用 token 或伪装 `user_id` 修复。

## 用户确定的共享规则

| 资源 | 创建阶段 | 广场调用者 | 禁止扩大到 |
| --- | --- | --- | --- |
| Skill | 从本人获准且启用的目录显式选择 | 仅在此员工的授权运行中调用已发布版本 | 调用者个人技能库、安装/下载/源码查看入口、发布者其他 Skill |
| 知识库/文档 | 从本人可读范围选择；发布另查转授权 | 仅经员工受控检索回答 | 原库浏览、全文/原文件下载、知识管理接口 |
| 凭据 | 本人/平台受控配置，独立声明 | 按调用者或管理员明确授权的服务身份使用 | 发布者 API 密钥、Cookie、代理口令、通用知识访问 token |
| 文件/历史/费用 | 当前调用者的线程 | 当前调用者可见的输出及审计 | 发布者私有目录、其他人的聊天和记忆 |

“可使用”不等于“可转授权”。SkillHub 安装记录只能证明安装来源，不能证明再分发权限；WeKnora 只读共享同样不能授权知识问答面向全广场。证据不明确时发布检查必须提示待授权，不能自动升级权限。

这里的“广场”特指**数字员工广场**，不改变 SkillHub 技能中心原有授权。用户已确认采用“只限制源码入口，允许模型执行时读取”：员工运行时可读取只读的已授权 Skill 包；员工调用者不因此获得源码浏览、下载、安装接口或发布者 API 密钥。实现不需要另建严格源码保密执行服务，但接口权限、目录隔离和资源转授权仍必须完成，不能只隐藏按钮。

“不开放下载入口”不是 DRM：可以读取 Skill 源码的执行模型仍可能在问答中复述片段；可以问答的知识也可能被连续提问重建。只读挂载仅防止修改，不保证机密性。严格源码保密不在当前已确认的边界内；将来若要求这种保证，需要单独评估受限执行服务与可支持的 Skill 类型。知识问答仍需限制每次命中数、片段大小、速率并记录审计，不能承诺“只能回答但绝对无法获知原文”。

## 前后端实施闭环

### 1. 创建与编辑

- 现有文本式员工构建器保持不变；使用独立资源表单，不把主聊天附件、Data Lake、模式控制全搬进构建器。
- Skill 保留官方 `null=跟随当前调用者已启用目录`、`[]=无 Skill` 语义。发布受控资源时必须转为显式选择和固定版本，不能发布一个会随查看者变化的依赖集合。
- 前端保留已失效的保存项供用户识别和移除；目录错误不得自动清空或扩大范围。未修改 Skill 时不在 PATCH/PUT 中提交该字段，避免仅改头像也覆盖绑定。
- 表单选择在后端写入时重新检查；模型文字、前端下拉项和用户提供的资源 ID 都不是权限证明。
- 员工详情查询缓存包含来源；失效或非法来源在页面显示明确错误并阻止发送、继续和重新生成，不无限重试、不回退到个人同名员工。历史元数据异常只使该员工执行失效，不能让整个历史列表崩溃；显示名称与稳定路径 ID 分离。
- 知识字段应采用官方默认范围的“默认、禁用、明确选择”分离思想，适配现有 WeKnora，不引入另一套 RAGFlow。明确区分完整库与具体文件；标签动态扩展必须重新授权或在发布时冻结文件集合，不能默默扩大为整库。
- 已实现 `knowledge_scope` v1：`inherit|disabled|selected`，最多 20 项明确库/文件；暂不开放标签绑定。前端未修改字段时不提交，选定模式无条目时不能保存。客户端名称被上游可信元数据替换，未授权资源、过期租户、错误文档父库均拒绝。API/模型不包含发布者凭据。选定范围在运行上下文两个入口覆盖完整五字段，编辑其他资料和工具更新不会丢失绑定。

### 1a. 创建后的修改与版本（本地链路已接通，生产验收未完成）

现状：表单修改草稿，`update_agent` 生成候选修改，用户在确认面板核对差异并明确确认后才提交。两者使用期望草稿修订号；过期写拒绝，不自动重试覆盖。共享员工及不可信 webhook 不注册/拒绝自修改工具。

- 两种编辑入口共用同一个服务：表单适合准确选择资源，对话适合调整职责/行为；对话先产生结构化候选变更，不直接改已发布文件。确认卡显示完整差异、资源增删、模型/工具变化、影响范围。
- 创建者的真实确认才能提交；模型输出“已确认”或工具结果不能代替用户确认。先提供私人试运行，再提供“保存草稿”和独立“发布新版本”，不得让一次普通员工聊天隐式发布。
- 三种身份分开：不可变 `employee_id`、私人 `draft_revision`、不可变 `publication_id/revision`。当前名称和 `agent_source` 仅是兼容入口，不是最终稳定版本主键；改显示名不换 ID，不让同名员工继承历史。
- 草稿保存使用服务端期望修订号/比较并更新，拒绝过期并发写，表单与聊天共用冲突提示。记录编辑者、时间、变更说明、上个修订号和内容摘要；不记录凭据或知识原文。批量字段更新及 SOUL 必须作为一个草稿修订提交。
- 发布冻结 SOUL、公开元数据、显式 Skill 内容摘要、知识范围与授权引用、所需工具和模型策略；配置快照不能包含 API 密钥。知识内容默认保持在线检索，冻结的是允许检索的范围，不伪称冻结了知识原文版本。
- 广场默认展示当前批准的发布版，新对话绑定该版；已有对话不静默升级。界面显示所用版本和升级提示，通过“新对话”重新准入，不就地改写旧会话和历史。
- 回退是选择已审计的旧内容再生成一次可追踪的发布动作；必须重新检查资源存在、授权有效及当前平台策略。回退不能复活已撤销授权、恢复创建者旧密钥或绕过安全封禁。
- 下架与撤销分开：下架关闭新的广场准入；资源授权撤销/安全封禁阻止后续受控工具调用，包括固定旧版本的线程。已经返回给用户或进入模型上下文的知识无法追溯擦除，界面不能承诺撤销历史披露。
- 私人副本只能复制可复制配置，不能把别人员工的“仅调用” Skill/知识授权复制进个人目录。管理者的排障权限同样不自动等于资源内容下载权。
- 所有引用未释放前不清理旧快照；历史显示、删除员工、停用创建者、并发编辑/发布、失败发布、版本回退、运行中撤权需单独回归。

本轮已完成的是团队发布定义层：`TeamPublicationStore` 在现有共享目录保存不可变配置/SOUL/头像版本，仅原子替换 `current.json` 指针；使用有时限的操作系统文件锁及 `expected_revision` 比较更新，不能用过期页面覆盖新发布。API 与页面发布/下架均携带期望版本，冲突刷新数据但不自动重发。下架追加撤下记录，不删除员工目录；只有原发布者能读取有界的版本元数据列表，不返回历史源码、SOUL 或路径。个人草稿修改不改写已发布版本。

本轮新增服务端 `employee-publication.json` 线程凭据，位于不可下载的线程元数据目录；只存员工身份、发布修订和摘要，不存定义或密钥。Gateway 先预读同一修订用于权限验证，再比较修订并落绑定；验证期间换版会拒绝此次运行，不用新版本冒充已验证版本。主 Agent 工厂按凭据读取同一份配置/SOUL；浏览器伪造版本号无效；下架阻断再次准入，保留旧凭据；共享 bootstrap 在落凭据前拒绝。

草稿存储 `read_definition/patch_definition` 要求期望修订，只合并传入字段，不 upsert、不改员工标识。HTTP 保存及提案确认已接入；文件配置/SOUL 使用持久化旧字节恢复日志，SQL 保留原行身份。**旧镜像不会恢复此日志，新发布索引也不兼容旧读路径；安全回退仍是发布阻断项。** 历史恢复到草稿后必须重新审查发布；不提供复制别人“仅调用”资源为个人可下载资源的入口。

### 1b. 现有服务器员工零丢失约束

- 本地没有执行服务器迁移。不得批量重建、清空目录、删除 SQL 员工记录，或用新模型序列化结果覆盖旧配置。
- 原 `users/*/agents`、SQL 个人记录、`team_agents` 与旧 `agents` 布局继续可读；普通目录/详情读取不创建发布快照。第一次线程准入或显式重发布时，旧团队定义被精确存档；原配置/SOUL/头像、记忆和自定义字段保持原样。新的草稿事务边界会建立锁文件，但不参加启动迁移或普通目录读取。
- 已采纳的旧发布目录不再参加启动时的分类重写；分类显示仍在响应中规范化。不在本次升级中改变私人 SQL 记录的 ID、配置、SOUL 或时间戳。
- 故障注入已覆盖快照写入中断、提交前失败、损坏发布索引、过期并发写和双进程争用。损坏的广场索引不使完好的私人员工列表失效；发布仍拒绝覆盖损坏记录。
- 上线前必须分别盘点文件/SQL/团队/旧布局的员工身份、数量、配置/SOUL/头像/绑定摘要，完成受限权限备份并验证可恢复；备份可能含私人信息，不在普通日志输出内容。未解释的减少、重命名、所有者变化或绑定变化均阻断放行。
- 共享盘跨节点锁与原子 rename 尚需生产等价 canary。当前通过的是本机多进程测试，不能据此声称 NFS 锁已验收。
- **回退兼容尚是发布阻断项**：旧 Gateway 不认识 `current.json`。需先上线兼容读取层并控制新格式写入，或交付经过演练的旧布局恢复方案，覆盖升级后新建/重发布/下架的员工。不能只回滚镜像就宣称新员工仍可见；不得因此删除新版本数据。
- 不自动清理历史版本或未提交的暂存目录；失败暂存不进入可见历史，后续清理需要独立保留策略。备份与发布切换之间还需阻止并发管理写入或使用一致性快照，不能仅比较一次数量。
- 已新增原始员工文件备份与新目录恢复演练：完整清单、对象哈希、完成封条、私有文件权限、复制后重盘点；数据变化则不封存成功。恢复明确拒绝已有目标目录，不能把旧快照覆盖到生产，也不能复活已撤销权限。此模块不包含 SQL 行或线程绑定，尚未接入生产维护门禁。

### 2. 发布版本与权限

- 以不可混淆的员工 ID、来源、发布修订号选择广场员工；个人同名项不得覆盖 Square 选择。
- 发布前核对每个依赖：当前启用、完整包、合法来源、转授权范围、固定版本、所需凭据、静态扫描。公共平台 Skill 也需平台级可委托策略，不能仅根据 `public` 字样推断。
- 快照包含必需脚本、模板和引用；拒绝链接、非普通文件、超限包、私密路径及检测出的密钥。扫描最终快照字节，不扫描后再复制可变化的源目录。
- 新版本在不可见暂存区准备完整，经跨 worker 发布锁及比较修订号检查后原子切换索引；失败保留旧版本。旧发布接口的删目录再创建流程已替换为上述版本存储；仍需共享盘跨节点验证，不能把本机多进程测试等同跨 Pod 验收。
- 未发布、已撤下、依赖失效分别呈现；旧员工不能自动补授共享权。历史记录可展示旧版本，但新执行重新准入。

### 3. 运行、子任务与沙箱

- Gateway 以真实调用者建立运行身份，服务端读取发布索引和授权并固定该次运行版本；不能接受客户端指定任意发布目录或发布者身份。
- 提示词目录、Slash 激活、Skill 工具策略、`describe_skill`、子任务、沙箱文件挂载必须指向同一份已准入目录。投影不能追加到调用者个人目录之上后仍让同名项回退。
- 每个线程投影位于 `thread_dir/agent-skills`，不在可下载的 `user-data` 下，挂载为只读；不注册到个人技能中心，不开放安装、升级、编辑、历史或导出接口。
- 依照已确认的入口限制边界，使用只读文件投影供执行模型读取，不以绝对源码保密为放行条件；完整授权、目录/挂载隔离与入口负向验收完成前仍不得启用新的共享发布入口。
- 重试、继续、子任务、定时任务和渠道都必须携带可验证的员工来源/修订号。渠道连接身份与网页调用者身份不能互换；定时任务按其所有者重新授权。撤销后不靠旧缓存继续获得授权。
- 员工记忆、检索结果和历史按调用者隔离；禁止从知识问答提取组织秘密进入跨用户/跨员工通用记忆。

#### 个人员工、广场员工与记忆边界（本地候选）

个人定义按所有者保存；发布产生独立的不可变定义/Skill 版本，不复制创建者记忆。
同名个人员工与广场员工用明确来源选择，已准入会话由服务端凭据固定版本，不再回退到同名个人项。
各调用者的线程记录、沙箱可写目录和会话摘要仍独立；共享的是获准发布的能力，不是使用者聊天数据。

本阶段对所有已准入广场发布版本（包括没有 `resource_policy_version` 的旧格式）关闭
长期记忆注入、回合后提取、记忆增删改查工具；主任务、子任务工具目录遵守同一规则。
自动压缩不注册长期记忆刷新钩子；手动压缩另外读取服务端绑定后应用相同限制，不能因绕过
Agent 构造而写进“调用者 + 同名个人员工”的记忆。原个人员工记忆设置不变，不建立所有广场使用者共用的记忆池。
这是保守隔离方案，不是已经实现“每位用户 × 每个发布员工”的跨会话长期记忆；若以后启用，
必须引入独立发布身份命名空间、权限及版本切换规则，不能复用个人同名路径。

不自动清理、迁移或擦除存量员工记忆；旧会话中已经注入的记忆或知识不能凭关闭开关追溯擦除。
存量会话兼容、新会话双用户测试、真实权限边界仍属于上线验收，本地通过不等于生产生效。

### 4. 知识问答授权

- 单独的服务端授权记录绑定：资源所有者/授权者、资源及子集、员工发布身份、允许的企业受众、检索用途、有效期、撤销版本。
- 创建者只有阅读权时需所有者授权；不能以已有缓存登录身份或 WeKnora 列表展示成功证明共享权。
- 发布和检索时读取新鲜权限；上游不可达则拒绝新的授权/检索，不能退回发布者全部库。
- 凭据只在 Gateway 检索适配器使用。只开放固定的有界检索动作，禁止通用 URL/路由透传。浏览、下载、管理 API 仍按调用者自己的原权限验证。
- 返回引用不能带可绕过授权的原文链接、签名下载 URL 或 owner token。资源删除、迁移、授权者停用、撤下员工和权限撤销都要使后续调用失效。
- 用户新增知识选择只能在已授权的员工边界内缩小范围；不能用提示词或伪造租户字段扩充授权。
- `inject_weknora_user_context` 仅用于真实调用者或可信内部任务所有者。共享固定知识另走 Gateway broker，授权与检索均复查真正 owner、租户和文件父库，整体检索 30 秒；查询限 2,000 字，响应限 2 MiB，最多 8 段各 1,800 字，每员工/调用者每分钟 30 次。引用去除下载链接，检索结束再次查撤销，不向沙箱/调用者传凭据。禁用知识时同时移除凭据和知识工具；子任务使用父业务线程而非子图 ID。

### 5. 生命周期、观测及兼容

- 发布者修改个人草稿不会立即改变已发布版本。依赖更新显式重发布；撤下阻断新执行并在下次工具/检索调用重新检查，不能保证抹去模型已读到的文本。
- 活动运行持有精确修订号；不可在请求中静默切换新版本。后台清理不得删除仍被引用的快照。
- 日志按真实调用者、员工/版本、资源授权、工具与结果码关联，禁止记录密钥/完整检索原文。失败显示明确的资源失效/待授权/执行错误，不反复 Thinking 或伪造成功。
- 回归普通聊天、PPT Master、图片/Office 上传、中文 PDF、read_file、SkillHub 开关及知识浏览原权限；不要为这项改造扩大 Gateway 副本/worker 数。

## 验收与放行清单

至少四种身份：A 创建者，B 无原资源权限的调用者，C 只给 A 阅读权的资源所有者，D 无关用户。

1. A 只能绑定本人允许且启用的 Skill/知识，A 读取但无转授权的资源不得直接向 B 发布。
2. B 没有 Skill 或有同名不同 Skill，均使用精确发布版本；D 的私有技能不可达。
3. B 不获得 A 的个人文件、聊天、密钥或知识浏览/下载权限；原有个人 Skill 保持不变。
4. 脚本/模板/引用可执行，禁用/撤销/失效明确失败；不靠回退到全局目录“恢复”。
5. 跨线程、子任务、继续/重试、定时/渠道入口、跨 Pod 版本切换、失败发布和回滚均保留授权边界。
6. 手动浏览器双用户走通最终输出，并对越权读取、下载、安装、伪造资源/租户 ID、撤销后复用进行负向验收。
7. 独立构建；保留精确回滚镜像；镜像预装和生产等价双容器 canary 通过后才安排维护窗口。全程不以静态 PASS 代替真实双用户业务验收。

当前验证矩阵和未关闭的放行项以 [热更就绪清单](digital-employee-release-readiness.md) 为准。各测试批次有重叠，不累加计数；本地模拟身份、模拟 WeKnora 和浏览器模拟接口不能替代生产双用户验收。尚无可执行生产 rollout 包，也没有修改生产数据库或现有员工。
