纯 HTML/CSS 版流程说明，不依赖 Mermaid CDN；所有图均采用竖向流程和判断分支表达。

核心原则： upstream/main 只作为官方来源，vendor/upstream-main 只负责同步官方代码，enterprise/integration 作为官方基线与企业功能的集成入口，所有企业开发从 feature/* 分支开始并通过 PR 合并。

5. 分支职责和保护规则

upstream/main官方来源，只读跟踪，不提交企业代码。
vendor/upstream-main本地保存的官方代码镜像，只做同步，不做业务开发。
enterprise/integration官方基线和企业功能的集成入口，建议设置为保护分支。
feature/*一个分支只做一类功能，例如 SSO、WeKnora、Kubernetes。
prod-* tag经过测试和回归验证后的生产发布版本，支持回滚。
旧 main历史产品分支，不作为新的 Feature 创建基线。
规则要求
官方同步先更新 vendor/upstream-main，再通过同步 PR 合并到 enterprise/integration。
功能开发只能从 enterprise/integration 创建 feature/*，不能从旧 main 或 upstream/main 创建。
代码合并所有变更必须经过 GitHub PR、代码 Review、CI 和安全检查，禁止直接 Push 集成分支。
发布测试通过后创建 prod-YYYYMMDD-编号，生产环境部署 tag，不直接部署开发分支。
逻辑集成分支 enterprise/integration 对应当前企业集成分支 codex/enterprise-consolidation-20260716。
