# SeaStandard 上线与入口配置

本次只发布前端页面及入口映射，不更新 Gateway、知识库服务或数据库结构。
首页沿用平台登录。新版前端部署后，已登录用户可直接访问：

`https://cnoocclaw.cnooc.com.cn/workspace/standards`

测试页面无需先创建门户数字员工或广场卡片。

## 运维需要做的事情

1. 按现有发布流程构建、发布与正式节点架构匹配的新版前端镜像。
   保存原镜像版本和前端部署配置，保留现有登录、Gateway 地址及其他运行参数。
2. 填写 [ConfigMap 示例](../deploy/examples/standards-portal-configmap.example.yaml)，
   部署到**现有前端所在的命名空间**。七项可逐项填写，空字符串表示未配置。
3. 将下面片段合并进现有前端 Deployment 中实际前端容器的 `env` 数组：

   ```yaml
   - name: STANDARDS_PORTAL_AGENTS_JSON
     valueFrom:
       configMapKeyRef:
         name: standards-portal-links
         key: STANDARDS_PORTAL_AGENTS_JSON
   ```

   这是一个环境变量条目，不是完整 Deployment；保留其他 `env`、`envFrom`、
   资源限制、副本数、探针和存储配置。

4. 按现有流程滚动更新前端，等待全部副本就绪，再进行下面的验收。

后续调整映射，只更新 ConfigMap 并重启或滚动更新前端，无需重新构建镜像。
运行中进程的环境变量不会随 ConfigMap 自动改变，仅刷新浏览器不会加载新配置。

## 七项对应关系

`STANDARDS_PORTAL_AGENTS_JSON` 的值是 JSON 对象，左侧键固定，右侧填写真实员工内部名称。

| 配置键          | 首页模块       |
| --------------- | -------------- |
| `qa`            | 标准知识问答   |
| `search`        | 标准信息检索   |
| `policy`        | 政策研究解读   |
| `comparison`    | 标准对比分析   |
| `applicability` | 标准适用性分析 |
| `compliance`    | 合规自检与预警 |
| `authoring`     | 标准编审辅助   |

员工内部名称可在“我的数字员工 → 编辑信息”中核对，也可从新建对话地址取得：

```text
/workspace/agents/<URL 编码后的内部名称>/chats/new
```

配置填写解码后的原始中文或字母、数字、连字符，最长 64 个字符。
展示名称 `display_name` 可能不同；不要填写完整 URL、`%E9...` 编码串或某次会话 ID。
页面会编码一次并生成同域新建对话链接，不需要配置域名。

业务方需先将目标员工发布共享，并确认普通用户拥有使用该员工及相关知识库的权限。
映射本身不创建员工或授予权限。未配置或格式无效的项，点击时显示未配置提示；
其余有效项仍可使用。整体 JSON 无法解析时，首页仍可打开，但各项按未配置处理。

## 验收与回退

- 使用普通业务账号登录，直接打开标准首页，确认桌面和手机显示正常。
- 逐项点击已配置模块，确认同一标签页进入对应员工的新建对话，中文名称正常。
- 检查未配置提示，以及原聊天和知识库入口；映射不完整时也可先测试首页。
- 需回退时恢复原前端镜像及原环境变量配置，再按现有流程更新前端。

本次不自动登记广场门户卡片，不增加返回首页按钮、隐藏或排序功能。
广场入口登记另行处理；热门展示继续使用平台现有开关。
