# 2.1.3 本地候选，尚未封包或发布

本目录从已发布 2.1.2 复制，修改范围是入口编排、程序化验收和截图模式。`MANIFEST.json` 是复制时的旧清单，不能用于本候选的验收或部署；正式封包时必须重新生成独立清单。历史候选和发布回执未修改。

`build` 直接生成带“点击查看完整日报”链接的完整 TXT，并在同一执行内完成输入、DOM、三宽布局及 PNG 结构验收。正常顺序为构建并程序验收、`present_files` 实际成功、读取同一 TXT 并回复一次；明确授权的机器人发送同样使用该文件。正常任务不再看图、OCR 或单独 `accept`。`visual_reviewed=false` 明确表示没有模型视觉审阅；程序验收不等同于真实平台发布。

仅 PNG 隐藏已核对身份的全局数据不完整提示框；HTML、JSON、TXT 和运费各自日期标记保持。公共核心模块 `common.py`、`market.py`、`research.py`、`report_renderer.py`、`browser_runtime.py` 与 2.1.2 逐字节一致。截图模式和验收变化集中在 `daily.py`；不能把程序化检查说成人工排版审阅。

平台须在每条 Bash 调用中按当前真实任务身份提供 `DEERFLOW_CONVERSATION_URL`，没有有效当前身份时必须清除继承值。该 URL 是公开定位信息，不是鉴权凭据。发布顺序是 **Gateway 上下文注入先上线并验收，再切换本 Skill**；混合版本滚动期间不启用本候选的无人值守外发。

未提供有效 URL 时仍可生成独立环境的四文件，但不返回可外发的正文状态，也不让模型寻找链接。曾绑定其他任务的项目拒绝复用。旧 `final-text` 仅保留兼容调用，同样要求有效的当前宿主 URL；调用者提供的工具结果不能代替当前身份。

离线单元测试使用合成网页、行情及 PNG。另有本机 Windows 真实浏览器生成的合成完整／运费参考样图，检查三宽布局和截图模式。不访问供应商、不发送消息；这些验证不等于生产 ARM64 浏览器、文件发布或机器人业务验收。上述核心保持仅相对已上线 2.1.2，不声称与作者原工程所有工作流完全等价。
